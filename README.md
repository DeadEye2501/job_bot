# Job Bot

Десктоп-приложение, которое автоматизирует поиск работы в Telegram-каналах. Бот опрашивает выбранные каналы, парсит вакансии через LLM, сравнивает их с вашим резюме по эмбеддингам, и отправляет HR-ам отклики через ваш собственный Telegram-аккаунт.

Всё локально: окно pywebview, SQLite, Pyrogram-сессия. Облако не требуется — LLM можно подключить локальный (LM Studio, Ollama) или внешний по OpenAI-совместимому API.

## Стек

- **UI** — pywebview поверх системного WebView2. Фронт на Svelte 5 (руны) + Vite, без роутера; собранный `dist` раздаётся окну по http своим мини-WSGI (`client/serving.py`), оттуда же идут вложения переписки.
- **Мост** — пакет `client/bridge/`: десять доменов по экранам (`vacancies`, `hr`, `companies`, `channels`, `blacklist`, `profile`, `stats`, `settings`, `system`, `wizard`) плюс хозяйство — asyncio-петля в фоновом потоке, единый конверт ответа, кольцо событий. Окно зовёт `api.<домен>.<метод>` через `js_api` pywebview; со стороны JS про мост знает ровно один файл — `client/web/api/bridge.js`.
- **Бот** — `backend/bot/`, Pyrogram-клиент в фоновом asyncio-loop, цикл опроса каналов в `backend/flows/`.
- **БД** — SQLite через async SQLAlchemy + Alembic-миграции. Креды (api_hash, password, session_string) шифруются через `cryptography` Fernet, ключ хранится в OS keyring.
- **LLM-адаптер** — `adapters/lm_chat.py`, `lm_embed.py`, `lm_models.py` поверх соединения из `lm_studio.py`, OpenAI-совместимый. Чат-модель и модель эмбеддингов настраиваются отдельно и могут жить на разных серверах.

## Что делает бот

Цикл `flows.IngestionPipeline`:
1. **Опрос каналов** — каждый `poll_interval_sec` пуллит свежие сообщения из активных Telegram-каналов через Pyrogram, по курсору последнего разобранного сообщения.
2. **Приём поста** — эмбеддинг текста, отсев перепостов и повторов по косинусной близости, отсев по чёрному списку; если в посте ссылка на статью Telegraph, её текст дотягивается и дописывается к объявлению.
3. **Парсинг** — LLM отвечает, вакансия это или самопрезентация соискателя, и раскладывает пост в структуру `ParsedVacancy` (грейд, стек, формат, зарплата и прочее).
4. **Оценка** — сверка с анкетой: грейд и формат отсекаются без модели, роль, языки и предпочтения — отдельным вызовом на каждый критерий, плюс счёт по совпавшим навыкам против порога `scoring_threshold`.
5. **Отклик** — для подходящих вакансий генерируется cover letter, сверяется с фактами о кандидате и отправляется HR-у в личку. Автоотправку можно выключить (`auto_apply`) — тогда вакансия остаётся в New, а отклик уходит вручную из карточки.
6. **Переписка** — входящие и исходящие сохраняются, привязываются к HR и вакансии, медиа скачивается; правка, удаление и прочтение доезжают апдейтами.
7. **Классификация ответов HR** — пачка сообщений от одного человека собирается дебаунсом и уходит в модель одним вызовом; исход двигает статус вакансии по графу из `docs/Статусы.md`. Молчание дольше таймаута переводит вакансию в Ghosting.

Режим бота переключается в окне: **Off** — цикл спит, **DM Only** — только переписка, **Full** — весь конвейер.

## Запуск

```powershell
pipenv install
cd client/web; npm install; npm run build; cd ../..
pipenv run python main.py
```

Фронт собирается своим сборщиком — окно раздаёт `client/web/dist`, а не исходники. Без сборки открывать нечего.

Первый запуск открывает мастер: приветствие → api_id/api_hash/телефон и код подтверждения (при облачном пароле — и он) → LLM для чата → LLM для эмбеддингов (по умолчанию берёт адрес и ключ у чата, своё только имя модели) → резюме файлом (PDF, Markdown или txt; разбор резюме моделью пока заперт, файл прикрепляется как есть) → готово. После этого открывается основное окно.

## Где лежат данные

- **Windows**: `%APPDATA%\JobBot\`
- **macOS**: `~/Library/Application Support/JobBot/`
- **Linux**: `${XDG_DATA_HOME:-~/.local/share}/JobBot/`

Внутри:
- `jobbot.db` — основная SQLite-база (вакансии, контакты, переписка, настройки).
- `jobbot.log` — журнал приложения; переходит на новый файл каждые 5 МБ, хранится четыре. В оконной сборке это единственное, что переживает закрытие окна: экран «Логи» показывает кольца в памяти.
- `jobbot.lock` — файл, на котором держится замок единственной копии.
- `sessions/` — Pyrogram-сессия (`.session`-файл).
- `media/` — вложения переписки и медиа из вакансий.

## Экраны

- **Профиль** — три вкладки: `CV` (анкета, грейды, форматы, языки, личные предпочтения, файл резюме), `Skills` (навыки по категориям, уровень и синонимы), `Experience` (места работы с достижениями и привязанными навыками). Всё автосохраняется.
- **Вакансии** — список с поиском, шестью сортировками и панелью фильтров (статус, каналы, компании, score, зарплата, грейд, формат, наличие HR-контакта, окно активности); справа карточка: смена статуса с пояснением, чипы, стек с подсветкой совпавшего, описание, контакты, заметки, таймлайн истории и событий, действия — отправить отклик, прогнать заново, связать с другим HR или компанией, показать исходный текст, удалить.
- **Контакты** — вкладки `Каналы`, `Компании`, `HR` (с перепиской), `Чёрный список`.
- **Статистика** — период (сегодня/неделя/месяц/квартал/всё время) и пять блоков: KPI с приростом, разбивка по статусам с кольцом, ответы HR по дням недели с медианой и долей без ответа, скилы, воронка по каналам с конверсиями.
- **Система** — две вкладки:
  - **Настройки** — Telegram (api_id/api_hash/телефон, вход и выход из сессии), LLM для чата, LLM для эмбеддингов, пайплайн (порог отсева, интервал опроса, сообщений за цикл, DM-сообщений на HR, симуляция отправки для стенда), опасная зона (полное удаление данных). Кнопки «Сохранить» нет: поля уезжают по `blur`/`change`.
  - **Логи** — кольца записей в памяти (по 500 на ERROR, WARNING и INFO, 1500 на DEBUG), фильтр по уровням со счётчиками, авто-обновление, раскрытие трассировки.
- **Нижняя полоса** — лампочки здоровья (база, Telegram-сессия, чат-LLM, эмбеддинги), ход текущего обхода, переключатель режима, ручной запуск цикла, счётчик непрочитанного. Пока хоть одна лампа не горит, режим и запуск заперты.

## Разработка

### Миграции

```powershell
pipenv run alembic revision --autogenerate -m "..."
pipenv run alembic upgrade head
```

При старте `main.py` сам выполняет `alembic upgrade head` (см. `backend/bootstrap.py`), отдельный шаг руками не нужен.

### Сборка `.exe`

Конфигурация в `JobBot.spec` (PyInstaller, single-file Windows-бандл).

```powershell
cd client/web; npm run build; cd ../..    # иначе в бандл уедет старый dist
pipenv run pip install pyinstaller        # один раз — в venv
pipenv run python -m PyInstaller JobBot.spec --clean --noconfirm
```

После сборки готовый файл лежит в `dist/JobBot.exe` (~44 МБ). Холодный старт — несколько секунд: онешот распаковывает себя во временный `_MEIPASS`-каталог. БД и логи живут в `%APPDATA%\JobBot`, рядом с .exe ничего не сохраняется — распространять можно как один файл.

Что вшито в бандл (см. `JobBot.spec`): собранный фронт `client/web/dist`, `alembic.ini` + `alembic/env.py` + `alembic/script.py.mako` + init-миграция, `client/icon.ico`. Hidden imports: `aiosqlite`, `keyring.backends.Windows`, `keyring.backends.fail`, `logging.config`, `logging.handlers`.

> Миграции с личными данными разработчика — seed (CV, опыт, навыки, подписанные каналы) и восстановление живой переписки — gitignored и в бандл не попадают: вместо них едут заглушки с теми же номерами ревизий из `alembic/bundled/`. Получатель .exe увидит чистую БД + first-run wizard.

### Структура проекта

```
backend/
  bootstrap.py        # alembic upgrade до подъёма окна
  bot/                # Pyrogram-клиент: соединение, цикл, отправка, апдейты
  flows/              # конвейер: опрос → приём → разбор → оценка → отклик, переписка
  domain/             # предметная логика без ввода-вывода, по модулю на предмет
  llm/                # промпты и разбор ответов модели, по модулю на предмет
  models/             # SQLAlchemy-модели, по модулю на предмет
  repository/         # запросы к базе, по модулю на предмет
  runtime_settings.py # in-memory-кеш конфигурации (TG creds, LLM endpoints, app-settings)
  log_buffer.py       # кольца записей для экрана «Логи», вымарывание секретов
  payloads.py         # dataclass-структуры для обмена с окном
  crypto.py           # Fernet поверх ключа из OS keyring

adapters/
  lm_studio.py        # соединение с OpenAI-совместимым провайдером
  lm_chat.py          # разговор с чат-моделью
  lm_embed.py         # эмбеддинг текста
  lm_models.py        # перечень моделей и проверка, что нужная отвечает
  telegram.py         # фабрика Pyrogram-клиента и отправка письма
  telegraph.py        # статья по ссылке из объявления
  db.py               # фабрика SQLAlchemy-engine

client/
  window.py           # окно pywebview: подъём хозяйства моста и его гашение
  serving.py          # раздача собранного фронта и вложений окну по http
  bridge/             # домены по экранам + хозяйство: петля, события, конверт ответа
  web/
    app/              # экраны и крупные части
    components/       # виджеты и диалоги
    state/            # логика без разметки
    styles/           # оформление, по файлу на блок
    api/              # bridge.js, events.js — единственное знание про pywebview
    dist/             # сборка Vite, её и раздаёт окно

alembic/
  versions/*.py       # миграции
  bundled/*.py        # заглушки личных миграций для сборки
  env.py

tests/                # питоновские тесты; тесты фронта — в client/web/tests

docs/
  maps/               # карты модулей, данных и фронта — собираются из кода
  Статусы.md          # граф переходов статусов вакансии (источник правды)

main.py               # CLI-entrypoint
config.py             # пути к user-data-dir
```

## Зависимости

- Python 3.13+
- `pyrogram` + `tgcrypto`
- `pywebview` (системный WebView2)
- `sqlalchemy` (async) + `aiosqlite` + `greenlet` + `alembic`
- `httpx`, `beautifulsoup4`, `cryptography`, `keyring`, `numpy`, `tzdata`
- Node.js — только для сборки фронта (Svelte, Vite)

Версии боевых пакетов закреплены точно (см. `Pipfile`): их обновление — отдельный осознанный шаг, а не побочный эффект установки dev-зависимости.

LLM-провайдер не привязан к коду — нужен любой OpenAI-совместимый endpoint с `/v1/chat/completions`, `/v1/embeddings` и `/v1/models`. Для LM Studio используется и его native `/api/v0/models` (фильтрация по `state=loaded` + `type` для UI-picker'а).

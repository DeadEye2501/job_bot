# Job Bot

Десктоп-приложение, которое автоматизирует поиск работы. Бот собирает вакансии из Telegram-каналов, с сайтов-агрегаторов и поиском по сети, разбирает их через LLM, сверяет с вашей анкетой и откликается: в Telegram от вашего аккаунта, кнопкой на агрегаторе, формой работодателя или письмом на почту.

Всё локально: окно pywebview, SQLite, Pyrogram-сессия. LLM можно подключить локальный (LM Studio, Ollama), внешний по OpenAI-совместимому API или Claude: через API Anthropic по ключу либо через установленный Claude Code по подписке. Модель эмбеддингов берётся с сервера или прямо из GGUF-файла на диске, без сервера.

Агрегаторы, «Поиск по сети», чтение страницы по ссылке и отклики через сайт делает агент — сессия Claude Code, которая водит браузер. Для него нужны Claude Code поставщиком чата и установленный браузер на Chromium. Без них работают каналы, Telegram-отклики и почта.

## Как пользоваться

1. **Подготовьте окружение.** Нужны аккаунт Telegram и его `api_id`/`api_hash` (выдаются на my.telegram.org → API development tools) и доступ к LLM: локальный сервер (LM Studio, Ollama), ключ OpenAI-совместимого API или Anthropic, либо установленный и залогиненный Claude Code. Для агрегаторов и «Поиска по сети» — Claude Code и браузер на Chromium (Chrome, Edge, Opera, Brave, Vivaldi или Яндекс.Браузер).
2. **Запустите `JobBot.exe`** (или из исходников — см. «Запуск»). Мастер первого запуска проведёт через вход в Telegram, выбор моделей для чата и эмбеддингов и загрузку резюме.
3. **Заполните профиль.** Если в мастере резюме разобрано моделью, большая часть уже на месте — проверьте вкладки `CV`, `Skills`, `Experience`, `Projects`. По анкете бот оценивает вакансии, пишет письма, отвечает на вопросы форм и заполняет резюме на сайтах, поэтому чем она точнее, тем точнее отклики.
4. **Добавьте источники** в «Контакты»:
   - `Каналы` → «Добавить канал»: `@username` канала или ссылка `t.me/...`;
   - `Агрегаторы` → «Добавить агрегатор»: адрес сайта, затем в его карточке «Войти» — откроется браузер, войдите на сайт и закройте окно. Бот проверит вход и подтянет ваши резюме на сайте; отметьте, каким откликаться;
   - «Поиск по сети» уже есть в списке агрегаторов, заводить его не нужно.
5. **Настройте пайплайн** в «Система → Настройки»: порог отсева, интервал опроса и положение автоотклика — «Только поиск», «Отклик с подтверждением» или «Автоотклик». Для начала удобнее «С подтверждением»: перед каждой отправкой бот покажет, что уйдёт, и дождётся вашего решения. Чтобы откликаться письмами, заполните раздел «Почта» (адрес и пароль приложения почтового сервиса).
6. **Включите бота** переключателем режима в нижней полосе: `Full` — искать и откликаться самому, `DM Only` — только следить за перепиской, `Off` — ничего не делать самому. Обход можно запустить и вручную кнопкой рядом, «Стоп» его прерывает. Пока какая-то из ламп здоровья слева не горит, бот не запустится — наведите на неё, чтобы узнать, в чём дело.
7. **Работайте с результатом.** Найденное — в «Вакансиях»: статус, балл, стек, контакты, история. Отсюда же можно откликнуться вручную, прогнать вакансию заново или завести свою кнопкой «Добавить вакансию» (поля, вставленный текст или ссылка). Ответы HR приходят в «Контакты → HR» и сами двигают статусы; счётчик непрочитанного — в нижней полосе. Если агенту нужна помощь — капча, вход, подтверждение, — полоса об этом скажет.
8. **Следите за итогами** на экране «Статистика», а если что-то пошло не так — в «Система → Логи».

Всё, что вы нажимаете сами, работает в любом режиме: режим решает только, что бот делает без вас.

## Стек

- **UI** — pywebview поверх системного WebView2. Фронт на Svelte 5 (руны) + Vite, без роутера; собранный `dist` раздаётся окну по http своим мини-WSGI (`client/serving.py`), оттуда же идут вложения переписки.
- **Мост** — пакет `client/bridge/`: одиннадцать доменов по экранам (`vacancies`, `hr`, `companies`, `channels`, `aggregators`, `blacklist`, `profile`, `stats`, `settings`, `system`, `wizard`) плюс хозяйство — asyncio-петля в фоновом потоке, единый конверт ответа, кольцо событий. Окно зовёт `api.<домен>.<метод>` через `js_api` pywebview; со стороны JS про мост знает ровно один файл — `client/web/api/bridge.js`.
- **Бот** — `backend/bot/`, Pyrogram-клиент в фоновом asyncio-loop; оборот (`bot/turn.py`) по очереди дожимает недоразобранное, опрашивает каналы и обходит агрегаторы.
- **БД** — SQLite через async SQLAlchemy + Alembic-миграции. Креды (api_hash, password, session_string, пароль почты) шифруются через `cryptography` Fernet, ключ хранится в OS keyring.
- **LLM-адаптер** — `adapters/lm_chat.py`, `lm_embed.py`, `lm_models.py` поверх соединения из `lm_studio.py`, OpenAI-совместимый. Чат-модель и модель эмбеддингов настраиваются отдельно и могут жить на разных серверах. Рядом — три надстройки, которые `lm_studio.py` выбирает по настройкам: Claude через официальный SDK Anthropic (`claude.py`, адрес `api.anthropic.com`), Claude через Claude Code без окна (`claude_code.py`, адрес `claude-code`) и эмбеддинги из GGUF-файла на llama-cpp-python (`gguf_embed.py`, пустой адрес и путь к `.gguf` вместо имени модели).
- **Claude Code** — для чата один фоновый процесс `claude.exe` на всё приложение, в потоковом режиме и без инструментов; после каждого запроса контекст сбрасывается `/clear`. Ключи API из окружения ему не передаются: вход — подписка человека.
- **Агент** — у каждой сессии свой процесс Claude Code (`adapters/claude_code_agent.py`) с MCP-сервером инструментов приложения: FastMCP + uvicorn на 127.0.0.1 с токеном в адресе (`adapters/agent_mcp.py`). Инструменты — `backend/agent/tools_*.py`, наставления — `backend/agent/prompts/`, устройство отдельных сайтов — `prompts/site_guides.py`. «Поиску по сети» дополнительно дан встроенный WebSearch.
- **Браузер** — Playwright, но не свой Chromium, а установленный браузер человека: первый найденный из Chrome, Opera, Brave, Vivaldi, Яндекс.Браузера, Edge (`adapters/browser.py`). У каждого агрегатора свой профиль; окно свёрнуто, загрузки запрещены. Вход на сайт человек делает в том же браузере, запущенном простым процессом без Playwright: Google отказывает ведомому браузеру. Окно агента, закрытое человеком, — это «Стоп».
- **Почта** — SMTP с паролем приложения, STARTTLS на 587, резюме вложением (`adapters/smtp_mail.py`).
- **Резюме** — текст из PDF (pypdf), DOCX (python-docx), Markdown и txt (`adapters/cv_text.py`), разбор моделью заполняет профиль.
- **Дочерние процессы** — Claude Code, браузер и драйвер Playwright на Windows привязаны к заданию с `KILL_ON_JOB_CLOSE` и закрываются вместе с JobBot, даже аварийно.

## Что делает бот

### Источники

- **Telegram-каналы** — каждый `poll_interval_sec` бот пуллит свежие сообщения из активных каналов по курсору последнего разобранного сообщения.
- **Агрегаторы** — любой сайт, который вы заводите по адресу. Агент-искатель ищет на сайте вакансии, появившиеся с прошлого обхода, но не больше «Вакансий с агрегатора» за раз; каждая находка проходит весь цикл до отклика, прежде чем агент ищет дальше.
- **«Поиск по сети»** — встроенная строка среди агрегаторов: агент ищет через WebSearch и не заходит на ваши агрегаторы, в Telegram и на сайты из чёрного списка.
- **Вручную** — окно «Добавить вакансию»: «Поля» заводятся как есть, «Текст» и «Ссылка» уходят боту на разбор. Ссылка на статью Telegraph или пост Telegram читается напрямую, прочую страницу читает агент. Повтор уводит к уже заведённой вакансии. Заведённая вами вакансия всегда New: разбор заполняет поля и балл, но не отсеивает её.

Каналы и агрегаторы включаются и выключаются и поштучно, и целым родом.

### Конвейер

1. **Приём** — эмбеддинг текста, отсев перепостов и повторов по косинусной близости, отсев по чёрному списку; если в посте ссылка на статью Telegraph, её текст дотягивается и дописывается к объявлению.
2. **Парсинг** — LLM отвечает, вакансия это или самопрезентация соискателя, и раскладывает текст в структуру `ParsedVacancy` (грейд, стек, формат, зарплата и прочее).
3. **Оценка** — сверка с анкетой: грейд и формат отсекаются без модели, роль, место, языки и предпочтения — отдельным вызовом на каждый критерий, плюс счёт по совпавшим навыкам против порога `scoring_threshold`.
4. **Отклик** — по положению автоотклика: «Только поиск» — не откликаться, «Автоотклик» — откликаться самому, «С подтверждением» — перед каждой отправкой показать вам, что уйдёт, и ждать вашего решения. Способы пробуются по порядку, пока один не сработает: Telegram HR, кнопка агрегатора выбранным резюме, форма работодателя, почта. Каждая ссылка и каждый адрес почты — отдельный способ. Письмо сверяется с фактами о кандидате; вопросы скрининга в форме агент отвечает по анкете.
5. **Переписка** — входящие и исходящие сохраняются, привязываются к HR и вакансии, медиа скачивается; правка, удаление и прочтение доезжают апдейтами.
6. **Классификация ответов HR** — пачка сообщений от одного человека собирается дебаунсом и уходит в модель одним вызовом; исход двигает статус вакансии по графу из `docs/Статусы.md`. Молчание дольше 14 дней переводит вакансию в Ghosting.

Когда агенту нужен человек — капча, вход на сайт, подтверждение отправки, — он ждёт до часа, а полоса внизу окна об этом просит.

### Агрегаторы: вход и резюме

Вход — кнопкой «Войти» в карточке агрегатора: открывается обычный браузер на профиле этого сайта, бот ждёт, пока вы закроете окно, затем агент проверяет вход и перечисляет ваши резюме на сайте. Отмеченное резюме идёт в отклики. «Перезаписать» и «Создать новое резюме» заполняют резюме на сайте по анкете.

### Режимы бота

Режим решает только, что бот запускает сам; нажатое вами в окне работает в любом режиме.

- **Off** — бот спит, переписку не читает.
- **DM Only** — только переписка: её классификация и Ghosting.
- **Full** — переписка плюс оборот: каналы, агрегаторы, «Поиск по сети».

## Запуск

```powershell
pipenv install
cd client/web; npm install; npm run build; cd ../..
pipenv run python main.py
```

Фронт собирается своим сборщиком — окно раздаёт `client/web/dist`, а не исходники. Без сборки открывать нечего. `playwright install` не нужен: агент водит установленный браузер.

Первый запуск открывает мастер: приветствие → api_id/api_hash/телефон и код подтверждения (при облачном пароле — и он) → LLM для чата (поставщик из списка: OpenAI, Anthropic, Claude Code, LM Studio, Ollama, OpenRouter или свой адрес) → LLM для эмбеддингов (источник «Сервер» — по умолчанию адрес и ключ чата, своё только имя модели; источник «Файл» — GGUF-модель на диске; Claude эмбеддингов не считает) → резюме файлом (PDF, DOCX, Markdown или txt: разобрать моделью и заполнить профиль, только прикрепить или пропустить шаг) → готово. После этого открывается основное окно.

## Где лежат данные

- **Windows**: `%APPDATA%\JobBot\`
- **macOS**: `~/Library/Application Support/JobBot/`
- **Linux**: `${XDG_DATA_HOME:-~/.local/share}/JobBot/`

Внутри:
- `jobbot.db` (+ `-wal`, `-shm`) — основная SQLite-база (вакансии, контакты, переписка, настройки, зашифрованная Telegram-сессия).
- `jobbot.log` — журнал приложения; переходит на новый файл каждые 5 МБ, хранится четыре. В оконной сборке это единственное, что переживает закрытие окна: экран «Логи» показывает кольца в памяти.
- `jobbot.lock` — файл, на котором держится замок единственной копии.
- `media/` — вложения переписки (`media/<hr_id>/`) и фото анкеты (`media/profile/`).
- `browser/` — профили браузера агрегаторов, по папке на сайт; удаляются вместе с агрегатором.
- `sessions/` — запасное место Pyrogram-сессии, если её строки нет в базе.

Всё это сносит «Удалить всё» в опасной зоне настроек. Мастер-ключ шифрования лежит в связке ключей ОС.

## Экраны

- **Профиль** — четыре вкладки, всё автосохраняется:
  - `CV` — фото, ФИО (и латиницей), гражданство, дата рождения, город, ожидаемая зарплата, контакты, образование, грейды, форматы, языки, «О себе», дополнительные инструкции для поиска, файл резюме и ссылка на резюме;
  - `Skills` — навыки по категориям, уровень и синонимы;
  - `Experience` — места работы: даты, обязанности, достижения, привязанные навыки;
  - `Projects` — проекты помимо мест работы: название, ссылка, «О проекте», стек.
- **Вакансии** — список с поиском, шестью сортировками и панелью фильтров (статус, каналы, компании, score, зарплата, грейд, формат, наличие HR-контакта, окно активности); кнопка «Добавить вакансию» (вкладки «Поля», «Текст», «Ссылка», переключатель «Отклик при создании»). Справа карточка: источник, смена статуса с пояснением, чипы, стек с подсветкой совпавшего, описание, HR и компания, контакты вакансии, заметки, таймлайн истории и событий. Действия — откликнуться (при нескольких способах — выбор, куда), прогнать заново, связать с другим HR или компанией, исходный текст, скрининг, перейти к источнику, удалить.
- **Контакты** — вкладки `Каналы`, `Агрегаторы`, `Компании`, `HR` (с перепиской), `Чёрный список`. У канала — «Прогнать сейчас» и сброс курсора; у агрегатора — вход, список резюме на сайте с выбором, каким откликаться, «Перезаписать», «Создать новое резюме», «Прогнать сейчас»; компании и HR сливаются.
- **Статистика** — период (сегодня/неделя/месяц/квартал/всё время) и пять блоков: KPI с приростом, разбивка по статусам с кольцом, ответы HR по дням недели с медианой и долей без ответа, скилы, источники (каналы и агрегаторы) с воронкой откликов и конверсиями.
- **Система** — две вкладки:
  - **Настройки** — Telegram (api_id/api_hash/телефон, вход и выход из сессии), почта (адрес и пароль приложения), LLM для чата и для эмбеддингов (тот же список поставщиков и выбор «Сервер / Файл», что в мастере, кнопка «Проверить»), пайплайн (порог отсева, интервал опроса, сообщений за цикл, DM-сообщений на HR, вакансий с агрегатора, автоотклик в трёх положениях), опасная зона (полное удаление данных). Кнопки «Сохранить» нет: поля уезжают по `blur`/`change`.
  - **Логи** — кольца записей в памяти (по 500 на ERROR, WARNING и INFO, 1500 на DEBUG), фильтр по уровням со счётчиками, авто-обновление, раскрытие трассировки, очистка списка.
- **Окно подтверждения** — в режиме «С подтверждением» показывает, что уйдёт работодателю: поля правятся, обязательные помечены; «Подтвердить», «Закончить» (не отправлять) или «Свернуть» в полосу.
- **Нижняя полоса** — лампочки здоровья (база, Telegram-сессия, чат-LLM, эмбеддинги), ход текущего обхода, переключатель режима, ручной запуск и «Стоп», «Откликнуться на все новые», значок обновления, счётчик непрочитанного, просьбы агента о помощи (капча, вход, подтверждение). Пока хоть одна лампа не горит, режим и запуск заперты; погасшая лампа переводит бота в Off.

## Разработка

### Миграции

```powershell
pipenv run alembic revision --autogenerate -m "..."
pipenv run alembic upgrade head
```

При старте `main.py` сам выполняет `alembic upgrade head` (см. `backend/bootstrap.py`), отдельный шаг руками не нужен.

### Сборка `.exe`

Конфигурация в `JobBot.spec` (PyInstaller, single-file Windows-бандл).

```powershell
cd client/web; npm run build; cd ../..    # иначе в бандл уедет старый dist
pipenv run pip install pyinstaller        # один раз — в venv
pipenv run python -m PyInstaller JobBot.spec --clean --noconfirm
```

После сборки готовый файл лежит в `dist/JobBot.exe`. Холодный старт — несколько секунд: онешот распаковывает себя во временный `_MEIPASS`-каталог. БД и логи живут в `%APPDATA%\JobBot`, рядом с .exe постоянно ничего не хранится — распространять можно как один файл. Временно рядом появляется только `JobBot.exe.new` — скачанное обновление до подмены.

### Сборка `.app` (macOS)

Мак-сборка живёт рядом с Windows-сборкой и её не трогает: свой `JobBot-macos.spec` и свои зависимости в `macos/Pipfile` (llama-cpp-python там собирается из исходников с Metal, добавлены Quartz и Cocoa из pyobjc). Там, где Windows-код завязан на WinAPI, на маке работает двойник рядом с ним (`*_macos.py`); выбирает его ветка `sys.platform == "darwin"`, а грузится он по имени строкой, чтобы в Windows-exe не попадал. Поддерживаются только Apple Silicon (arm64).

Собирается на GitHub Actions (`.github/workflows/macos.yml`, раннер `macos-14`): тесты двойников из `macos/tests`, фронт, бандл, проверка запуска собранного, архив `JobBot-macos.zip` артефактом. Локально, на маке:

```bash
cd client/web && npm run build && cd ../..
export PIPENV_PIPFILE=macos/Pipfile CMAKE_ARGS="-DGGML_METAL=on"
pipenv install --dev
```

Готовое — `dist/JobBot.app`. Подписи Apple у него нет, поэтому скачанное macOS при первом запуске не пускает: открыть правым кликом → «Открыть» (на новых macOS — «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть») или снять карантин `xattr -cr JobBot.app`. Перед первым запуском `JobBot.app` переносится в «Программы» или другую свою папку: открытое через «Открыть» прямо из «Загрузок» macOS запускает с копии только для чтения, и самообновлению некуда положить новую версию. По той же причине обновиться не выйдет у пользователя без прав на запись в папку, где лежит приложение.

### Обновление

Собранный exe при запуске спрашивает последний релиз репозитория `DeadEye2501/job_bot` на GitHub (`backend/update_download.py`, `adapters/github_release.py`). Релиз без файла `JobBot.exe` или без его контрольной суммы обновлением не считается. Значок круглых стрелок в нижней полосе серый — проверить вручную, акцентный — найдена версия новее. По нажатию акцентного:

1. новый `JobBot.exe` скачивается рядом с запущенным как `JobBot.exe.new`, ход — в полосе; скачивание занимает место прогона, «Стоп» его отменяет;
2. файл сверяется с контрольной суммой релиза; не сошлось — удаляется;
3. приложение копирует себя в `%TEMP%\JobBot-update.exe` и запускает копию с `--update` (`backend/updater.py`), а само закрывается штатно;
4. копия ждёт выхода приложения, заменяет `JobBot.exe` скачанным и запускает его; свой журнал пишет в `%TEMP%\JobBot-update.log`, журнал приложения не трогает;
5. новый exe при старте убирает `JobBot.exe.new` и копию.

Пока идёт прогон, значок заперт. При запуске из исходников (`python main.py`) проверить можно, а обновиться — нет: подменять нечего. Номер версии — в боковом меню.

На маке ход тот же, а файл свой: номер версии и релиз общие на обе системы, в релизе лежат `JobBot.exe` и `JobBot-macos.zip`, и каждая сборка ищет только свой (`backend/updater_macos.py`). Мак-сборка качает zip рядом с `JobBot.app` как `JobBot-update.zip`, сверяет сумму, распаковывает и отдаёт подмену процессу `sh`: тот ждёт выхода приложения, ставит новый `JobBot.app` на место старого (не вышло — возвращает старый) и открывает его. Свой журнал подменщик пишет во временную папку, в `JobBot-update.log`. Остатки — zip, папку распаковки, отведённый старый бандл — убирает следующий запуск.

### Выпуск версии

1. Поднять номер в `backend/app_version.py` (`VERSION`).
2. Собрать exe (раздел выше).
3. Выложить релиз с тегом `v` + номер и файлом `JobBot.exe`:

   ```powershell
   gh release create v1.2.0 dist/JobBot.exe --title "1.2.0"
   ```

GitHub CLI ставится `winget install GitHub.cli`, вход — `gh auth login`.

Мак-сборку к релизу добавлять руками не нужно: опубликованный релиз запускает `macos.yml`, и тот кладёт `JobBot-macos.zip` в файлы того же релиза.

Что вшито в бандл (см. `JobBot.spec`): собранный фронт `client/web/dist`, `alembic.ini` + `alembic/env.py` + `alembic/script.py.mako` + init-миграция, `client/icon.ico`, драйвер Playwright (`collect_data_files('playwright')`), библиотеки движка `llama_cpp` (`collect_dynamic_libs`). Hidden imports: `aiosqlite`, `keyring.backends.Windows`, `keyring.backends.fail`, `logging.config`, `logging.handlers`, `llama_cpp`, `playwright.async_api` и подмодули `anthropic`, `mcp` (без `mcp.cli`) и `uvicorn`.

Модель эмбеддингов в бандл не вшивается: путь к `.gguf` задаётся в мастере или настройках, файл читается с диска при первом обращении. Claude Code тоже не вшивается — для этого поставщика и для агента он должен быть установлен (`claude` в `PATH`) и залогинен под подпиской. Браузер не вшивается — берётся установленный.

> Личных данных разработчика в миграциях нет: получатель .exe увидит чистую БД и мастер первого запуска.

## Зависимости

- Python 3.13 (колесо llama-cpp-python собрано под cp313)
- `pyrogram` + `tgcrypto`
- `pywebview` (системный WebView2)
- `sqlalchemy` (async) + `aiosqlite` + `greenlet` + `alembic`
- `httpx`, `beautifulsoup4`, `cryptography`, `keyring`, `numpy`, `tzdata`
- `anthropic` — Claude по API
- `playwright` — браузер агента
- `mcp` (FastMCP) + `uvicorn` — сервер инструментов агента
- `pypdf`, `python-docx` — текст резюме из PDF и DOCX
- `llama-cpp-python` — эмбеддинги из GGUF-файла (готовое колесо cp313 win_amd64 по ссылке в `Pipfile`)
- Node.js — только для сборки фронта (Svelte, Vite, тесты на vitest)
- Claude Code — для поставщика «Claude Code» и для агента, ставится отдельно
- Браузер на Chromium (Chrome, Opera, Brave, Vivaldi, Яндекс.Браузер или Edge) — для агента

На маке список тот же, но свой — `macos/Pipfile`: llama-cpp-python ставится из исходников с Metal (нужны Xcode Command Line Tools), `pywebview` рисует системным WebKit, сверху `pyobjc-framework-Quartz` и `pyobjc-framework-Cocoa`, PyInstaller — в dev-зависимостях.

Версии боевых пакетов закреплены точно (см. `Pipfile`): их обновление — отдельный осознанный шаг, а не побочный эффект установки dev-зависимости. Dev-зависимости: `pytest`, `pytest-asyncio`, `ruff`.

LLM-провайдер не привязан к коду — нужен любой OpenAI-совместимый endpoint с `/v1/chat/completions`, `/v1/embeddings` и `/v1/models`. Для LM Studio используется и его native `/api/v0/models` (фильтрация по `state=loaded` + `type` для UI-picker'а). Claude подключается без OpenAI-совместимости — своими надстройками (см. «Стек»).

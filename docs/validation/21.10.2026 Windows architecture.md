# Проверка этапа A: выделение Windows-модуля

Дата: 21.10.2026. Исходный commit: `daaef96`.
Результат: архитектурный этап выполнен; macOS/Linux-реализации не начаты.
Изменения не закоммичены.

## Выполнено

- Windows-операции выделены в `adapters/platforms/windows/` по предметам.
- Общие точки входа выбирают реализацию один раз; `ctypes`, WinForms,
  `msvcrt`, Explorer, Windows-флаги запуска и Job Object находятся внутри
  Windows-пакета.
- Старые публичные входы управления процессами и обновлятора сохранены.
- Операции, ещё не реализованные для macOS/Linux, явно отказывают.
  Существующие переносимые `flock` и PATH-поиск CLI сохранены.
- Исправлен импорт `errno.EDEADLOCK` на Darwin.
- Windows-установка обновления защищена на уровне UI, бота, скачивания,
  подменщика и `--update`. На неподдержанных ОС файлы не очищаются.
- Для динамически выбираемого Windows-пакета добавлены hidden imports
  в существующий `JobBot.spec`; формат onefile не менялся.
- Тестовые подмены перенесены на новые границы. Изоляция данных тестового
  стенда и его дочерних процессов исправлена для запуска на Mac.

Перечень операций и соответствие старых/новых файлов:
[build_tools/README.md](../../build_tools/README.md).

## Обнаруженная проблема тестового стенда

Первый полный прогон дал 3959 успешных тестов и два падения: отдельные
процессы тестов журналирования учитывали только `APPDATA` и на macOS создали
тестовые `jobbot.db` и `jobbot.log` в стандартном пользовательском каталоге.
Изоляция исправлена до импорта `main` в каждом дочернем процессе.

После проверки времени создания и тестовых маркеров эти два созданных
прогоном файла и их пустой каталог удалены с разрешением пользователя.
Повторный полный прогон прошёл; отдельно проверено, что этот каталог заново
не создаётся. Рабочее приложение, реальный keyring и учётные записи
пользователя не запускались.

## Открытая проверка перед окончательной передачей контрибьюта

На Windows выполнить pytest, собрать прежним spec `JobBot.exe`, проверить
мастер/изменение рамки, браузерный вход, очистку потомков при аварии,
показ окна второй копии и обновление старой frozen-версии новой. До этого
нативная Windows-регрессия остаётся открытой. По принятому плану это не
блокирует следующий этап локальной реализации macOS, но не позволяет
объявить Windows exe проверенным.

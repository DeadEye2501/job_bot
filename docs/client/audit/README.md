# Замер переноса: старое окно против нового фронта

Снято 15 августа 2026, после того как этап 5 был отмечен закрытым и человек
впервые посмотрел на результат глазами.

**Что мерили.** Задание этапа было — перенести существующий дизайн **один в
один, без единого изменения**. Перенос делался не по разметке, а по пересказу:
агент читал старое окно и описывал словами, что там есть, а сборка шла по
описанию из готовых компонентов. Замер считает, насколько результат разошёлся
с образцом.

**Образец.** `client/web/main.html` (15 628 строк) и `client/web/wizard.html`
(1225) — снесены слайсом В1, достаются из истории:

```bash
git show ac2bfb9^:client/web/main.html   > main.html
git show ac2bfb9^:client/web/wizard.html > wizard.html
```

**Как читать отчёты.** Каждый — таблицы `элемент | было | стало | род
расхождения`. Роды: **пропало / лишнее / изменено / размер / цвет / порядок**.
Строка может нести два рода и тогда посчитана в обоих.

## Пять сквозных причин

Расхождений шесть с половиной сотен, но заведены они пятью решениями и одним
приёмом работы.

1. **Раскладка сменилась молча.** Везде, где стояли две панели `275px | 1fr` —
   список слева, карточка справа, — стал список во всю ширину и окно поверх
   него. Одно это решение перестроило четыре экрана: вакансии и три вкладки
   контактов. Ни в плане, ни в записях слайсов оно не объявлено.
2. **Пропали переходы между карточками** — больше десятка: кольцо статистики →
   вакансии, мини-список → вакансия, человек → Telegram, компания → сайт,
   «связать по разобранному имени», вакансия и человек в чужой карточке. Экраны
   стали тупиками.
3. **Пропали мелкие сущности, которых не было в пересказе:** значки пустых
   состояний, кнопка очистки поиска, подсказчик в чёрном списке, шапка таблицы
   отсева, встроенные фотографии в переписке, поп-ап непрочитанных чатов,
   карточки-подсказки мастера, строка состояния мастера.
4. **Тексты переписаны там, где надо было скопировать** — десятки подписей
   кнопок, полей, колонок и пустых состояний.
5. **Палитра — единственное, что сошлось честно.** Во всех семи отчётах
   значения совпали до цифры; расхождения рода «цвет» — это выбор другой
   переменной в новом коде, а не искажённое значение.

## Четыре поломки, не про вид

Найдены тем же замером и к дизайну отношения не имеют:

- **ползунок порога отбора не имеет шарика вовсе** — `styles/pipeline.css` и
  `styles/slider.css` склеивают `::-webkit-slider-thumb` с `::-moz-range-thumb`
  в один список селекторов; неизвестный движку псевдоэлемент делает
  недействительным всё правило, и Chromium отбрасывает оба. В образце они были
  разведены по движкам именно поэтому;
- **число рядом с ползунком не обновляется** — своё состояние экран не правит,
  а перечитывания после записи нет;
- **подборщик привязки срабатывает по одному нажатию** — пропали отметка
  «текущий», кнопка «Связать» и её запор: промах мышью меняет привязку без
  подтверждения;
- **Escape и Enter в модальных окнах не работают.**

## Открытый вопрос про цвет

Акцент в CSS обеих версий один и тот же — `#64f20c`, не менялся с первого
коммита. На экране же кнопки разные: старая рисуется `#24ed32`, новая
`#74eb57`, при этом нейтральные подложки в том же снимке совпадают дословно
(`#2d2d2f`, `#3d3d3f`). Значит красит не CSS, а вывод: серое лежит на
нейтральной оси и не сдвигается, насыщенное сдвигается по-разному у
QtWebEngine и у WebView2. Ждёт ответа человека про HDR и автоматическое
управление цветом.

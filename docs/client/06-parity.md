# Этап 6. Сведение фронта с образцом

> **Для исполнителя.** ОБЯЗАТЕЛЬНЫЙ СУБ-СКИЛЛ: `free-hands:keeping-code-clean` —
> слайс-флоу, ревью отдельными агентами до коммита, красная фаза до кода.
> Галочки роадмапы ставятся по факту сделанного.

**Цель.** Свести нынешний фронт с образцом до буквы: 681 расхождение из
[audit/README.md](audit/README.md) закрыто, 143 пропавших элемента вернулись,
64 добавленных сверх образца сняты, четыре поломки не про вид починены.

**Метод.** Правка идёт **по разметке, а не по пересказу.** На каждый слайс из
истории достаётся кусок образца, кладётся рядом с нынешним файлом и сводится
построчно. Таблицы замера — чек-лист в конце слайса, а не источник правок:
источник — сам образец.

Именно подмена метода завела все 681 расхождение. Этап 5 строил по описанию
словами; пересказ теряет то, чего в нём не назвали, а назвать всё нельзя.

**Стек.** Svelte 5.56.8, Vite 8.2.0, Vitest 4.1.10, окружение тестов `node`.
Пять слоёв в `client/web/`: `api`, `state`, `components`, `app`, `styles`.

## Как нарезано

**Одна область замера — один слайс.** Семь отчётов замера, семь слайсов, плюс
полное ревью. Мельче не режем нарочно: у каждой области свой общий файл
оформления (`contacts.css` — 274 строки на четыре вкладки, `vacancy-card.css` —
на карточку с подборщиками), и разрез внутри области заставил бы править один
файл дважды, каждый раз со своим кругом ревью и коммитом. Обвязка вокруг
правки вышла бы дороже самой правки.

Две области тяжёлые — контакты (177 расхождений) и карточка вакансии (165).
Если слайс не закрывается, он делится **тогда**, по месту, а не заранее.

## Как идёт работа

Решено человеком 15 августа 2026, действует на весь этап. Читается один раз в
начале сессии, потом не перечитывается.

**Два-три слайса за сессию, дальше — новая с чистого листа.** Главный расход
здесь не правки, а чтение образца и таблиц замера: семь слайсов в один контекст
не влезают. План для того и написан подробно, чтобы новая сессия начиналась с
него, а не с разведки заново.

**Слайсы идут подряд, без остановок между ними.** Человек смотрит на экран один
раз — в конце, перед итоговым ревью (слайс 8, шаг 1). Согласования между
слайсами не спрашивать.

**Порядок внутри слайса:**

1. прочитать карты — один раз в начале слайса, не перед каждой правкой;
2. достать образец из истории в `$TEMP`;
3. написать **все** красные тесты слайса разом, прогнать, увидеть красными;
4. код до зелёного;
5. свести с образцом построчно;
6. пройти таблицу замера — каждая строка закрыта или объяснена;
7. **пересобрать карты** — до ревью, иначе рецензент прочтёт карту без того,
   что слайс добавил, и не найдёт ничего по определению;
8. ревью;
9. правки по находкам;
10. коммит.

### Ревью между слайсами — один агент

Обычный порядок скилла — четыре агента после каждого слайса. Здесь он урезан
до одного, и урезан не поровну: **из четырёх измерений от отсрочки дорожает
только одно.**

| измерение | когда | почему так |
|---|---|---|
| **ошибки** | после каждого слайса | поломка, внесённая во втором слайсе и найденная в восьмом, лежит под пятью слайсами чужих правок |
| дубликаты | в итоге | ищутся по картам, а не по диффу — им безразлично, когда смотреть |
| манифест | в итоге | находит то же самое; семь правил из шестнадцати машина держит на каждой записи |
| тесты | в итоге | красная фаза уже доказала, что тест умеет падать; второй прогон того же набора ничего не добавляет |

**Агент по ошибкам читает только дифф** — ни карт, ни прогонов тестов. Модель —
`sonnet`, не `opus`: читать дифф и искать поломку не та работа, за которую
стоит платить верхней моделью. Итоговое ревью идёт на `opus`.

Задание собирается по `superpowers:requesting-code-review`, не с нуля — хук
отклоняет запуск, если шаблона в задании не видно. Отчёт агент пишет в файл, в
ответ возвращает сводку. Потолок — десять минут; дольше — гасить, измерение
уходит в итог. Рабочего дерева ему не давать: слайс ещё не закоммичен, в свежем
дереве его нет вовсе.

**Мутаций между слайсами нет ни у кого** — ни у исполнителя, ни у агента.

### Что держит слайс бесплатно

Не стоит ни токена и работает само:

- машинные проверки на каждой записи — повтор тела, размер файла, сложность
  функции, границы слоёв, `<style>` в компоненте, цвет мимо палитры;
- красная фаза;
- проход по таблице замера.

### Чем платим за урез

Нарушение манифеста или повтор, заведённые в первом слайсе, найдутся в конце —
и чинить их придётся в семи местах сразу. Смягчает то, что границы слоёв и цвет
машина повторить семь раз просто не даст. Второе: найденное итоговым ревью
ляжет поверх семи коммитов, а не внутрь своего.

## Общие запоры

Действуют на каждый слайс, повторно в слайсах не написаны.

- **Образец достаётся из истории, в репозиторий не кладётся:**
  ```bash
  git show ac2bfb9^:client/web/main.html   > "$TEMP/main_old.html"    # 15 629 строк
  git show ac2bfb9^:client/web/wizard.html > "$TEMP/wizard_old.html"  #  1 225 строк
  ```
  Устройство `main_old.html`: `<style>` 20–3976, разметка `<body>` 3978–4051,
  `<script>` 4055–15625. Номера строк во всех слайсах — по этому файлу.
- **Границы слоёв держит машина, без храповика.** `<style>` внутри компонента,
  файл оформления вне `styles/`, ввоз вверх по слоям, цвет мимо
  `styles/palette.css` — отказ в записи. Цвет пишется переменной, всегда.
- **Палитра сошлась с образцом до цифры** — её не трогаем. Расхождения рода
  «цвет» означают выбор не той переменной, а не другое значение.
- **Предел файла — 500 строк**, сигнал — 300. Самый большой файл фронта сейчас
  `VacancyCard.svelte` (321), запас есть, но возврат пропавшего его съест.
- **Тексты копируются из образца дословно**, включая регистр и прочерки.
  Переписанная подпись — расхождение того же рода, что и сдвинутый отступ.
- **Мост не трогаем.** Если пропавшему элементу нужны данные, которых мост не
  отдаёт, — это находка для человека, а не повод править `client/bridge/`.
- **Прогон фронта:** `cd client/web && npm test`. Прогон питона:
  `python -m pytest tests/client -q`. Оба зелёные до коммита.

## Решения, принятые до начала

**Лишнее снимается до буквы образца.** Все 64 отметки рода «лишнее» — закрытие
панели кликом по затемнению, кнопка «Закрыть» в подвале, свои пустые состояния,
счётчики строк, `.modal-title`/`.modal-subtitle` — снимаются вместе с остальными
правками слайса. Отдельного решения по каждой не требуется.

**Тестами сторожится только поведение.** Красная фаза слайса — на четыре
поломки, на вернувшиеся переходы между экранами и на снятое лишнее. Чистые
значения вида (`padding`, `width`, `font-size`) тестами не сторожатся: тест,
читающий объявление CSS, — ровно тот тест, против которого написано правило 13.

**Отсюда следствие, которое меняет код.** Нынешние тесты грузят только `state/`
и `api/` — ни одного файла `app/` или `components/`. Значит поведение, которое
надо сторожить, должно жить в `state/`, а компонент — только звать. Это правило
10 манифеста, и слайсы ниже переносят логику туда, где её видно тестам.

**Раскладка двух панелей возвращается.** Образец держит `275px | 1fr` — список
слева, подробности справа — на вакансиях и на трёх вкладках контактов. Нынешнее
окно поверх списка снимается. Образец раскладки задаёт слайс 2, слайсы 3 и 4
повторяют его.

```js
describe('клавиши модального окна', () => {

  it('прочие клавиши ничего не значат', () => {
    expect(modalKey({ key: 'a', target: { tagName: 'INPUT' } })).toBe(null);
  });
});
```

```js
// Что значит клавиша в открытом модальном окне.
//

const MULTILINE = new Set(['TEXTAREA']);

export function modalKey(event) {
  if (event.key === 'Escape') return 'close';
  if (event.key === 'Enter' && !MULTILINE.has(event.target?.tagName)) return 'confirm';
  return null;
}
```

## Что этот этап не делает

**Вопрос про цвет не решается здесь.** Акцент в CSS обеих версий один и тот же
(`#64f20c`), а на экране кнопки разные: старая `#24ed32`, новая `#74eb57`, при
совпадающих нейтральных подложках. Красит не CSS, а вывод — насыщенное
по-разному сдвигается у QtWebEngine и WebView2. Это отдельный вопрос к человеку
про HDR и автоматическое управление цветом, и правкой стилей он не чинится.

**Мост не трогается.** Если пропавшему элементу нужны данные, которых мост не
отдаёт, слайс останавливается и вопрос идёт человеку.

**Что такое «календарь» из пункта Б8 — решено 15 августа 2026.** Это свой
компонент выбора даты; другого календаря в проекте не было. Отдельного
вида-календаря в образце не существовало никогда, а то, что им выглядело, — это
`flatpickr` у двух полей периода в отборе «Активность в течение» и у полей
периода в карточке места работы. Библиотека уехала вместе с `vendor/` слайсом
В1, поэтому компонент пишется свой: слайс 2 его заводит, слайс 5 применяет.

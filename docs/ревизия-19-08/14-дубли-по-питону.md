# 14. Сплошной поиск дублей по питону

Участок: весь боевой питон — `backend/`, `adapters/`, `client/` (кроме `client/web`),
`main.py`, `config.py`. Тесты и `tools/` не входили. Предмет один: дубли **между**
модулями, которых не видит рецензент своего участка.

## Как мерили

Питон из окружения проекта (3.13). Четыре прохода по **151 файлу / 24 360 строкам**:

1. **Точный:** тела **999 функций** (0 ошибок разбора), нормализация — имена→позиционные
   метки, литералы→имена типов, декораторы/аннотации/докстрока сняты; сравнение по
   `ast.dump`. → **17 групп**, 7 из них с телом ≥3 строк.
2. **Похожий:** `SequenceMatcher` по последовательности типов узлов, **порог 0.85**, отбор
   ≥25 узлов и ≥6 строк → **63 пары**; повторный прогон с отбором ≥45 узлов и порогом 0.78
   → 52 пары.
3. **Куски внутри тел:** одинаковые нормализованные последовательности ≥3 инструкций /
   ≥30 узлов → **34 группы**, 13 междуфайловых.
4. **Строки:** одинаковые последовательности непустых некомментарных строк ≥5 → **23
   группы**; повторённые строковые литералы ≥14 знаков → **59 групп**.

Все результаты первых трёх проходов прочитаны глазами по исходникам.

## Сделано хорошо

- **`client/bridge/mark.py`** (`MarkSubject` + `mark`/`unmark`) и **`pickers.py`**
  (`PickerSubject`) сводят три предмета таблицей.
- **`client/bridge/answer.py`** — единый конверт; `bad_fields` убрал «три строки в каждом
  слоте на сорока восьми местах», и по всему мосту нашлось ровно **одно** место, которое
  эту фразу всё ещё пишет руками.
- **`refusals.py`**, **`page.py`**, **`wire.py`**, **`bot_stop.py`**, **`merging.py`**,
  **`blacklist_marks.py`**, **`spellings.py`**, **`skill_names.py`**, **`llm/answers.py`**,
  **`llm/external.py`** — каждый закрывает свой класс повторов. `wire.py` (374 строки, 14
  переводчиков строк в словари) не дал ни одной пары выше порога.
- `normalize_username` — единственный разбор ника на весь проект: 4 зовущих, ни одной
  ручной копии `lstrip("@")` мимо него.
- `UNREAD_INCOMING`, `PARSED_ONLY`, `LAST_VACANCY_ORDER`, `VACANCY_NEIGHBOURS`,
  `ALLOWED_AUTO_TRANSITIONS` объявлены по одному разу; расписанных руками копий — одна.

## Вердикт

**Участок в порядке?** С правками.

Разобрано **999 функций** в 151 файле (24 360 строк), ошибок разбора нет. Выше порога
точного совпадения — **17 групп**, выше порога похожести 0.85 — **63 пары**, одинаковых
кусков внутри тел — **34 группы**, одинаковых пятистрочий — **23 группы**, повторённых
литералов — **59 групп**. После ручной проверки осталось **13 находок**: 3 важных и 10
мелких. Отсеяны три рода ложных срабатываний — объявления колонок моделей SQLAlchemy,
обвязка «сессия → `select` → словарь» вокруг предметно разных запросов, и места, где общее
уже вынесено.

Критического нет. Но два дубля крупные и уже разошлись — параллель `Companies`/`Hr` (около
140 строк на класс, четыре расхождения) и рамка данных в семи наставлениях модели (семь
разных текстов, три без запрета исполнять команды из чужого текста).

# План: починка по журналу

**Цель:** закрыть то, что журнал приложения показал сломанным или вводящим в
заблуждение с 10.10.2026: тихие потери вакансий и переписки, лишний расход
лимита Telegram, утечку и шум.

**Порядок работы:** пункт за пунктом — тест до кода и красным, код, весь набор
зелёным, карты, ревью отдельными агентами, правки, коммит. После всех пунктов —
полное ревью. Мутаций нет.

Тесты питона: `pipenv run python -m pytest <файлы> -q -p no:cacheprovider`.
Тесты фронта: `cd client/web && npx vitest run <файл>`.

## 1. Догон переписки не ищет HR по нику при каждом запуске

Клиент держит сеанс в памяти и после запуска не знает собеседников; догон
ищет почти каждого HR по нику (`contacts.ResolveUsername`, ~145 запросов), и
Telegram запрещает такой поиск на 6–19 часов — на весь аккаунт: у новых
вакансий не находится HR, письма за время простоя не подтягиваются.

- [x] Догон читает только собеседников из списка переписок, когда список
  прочитан целиком: у остальных переписки нет, а попытка уходит в розыск по
  нику. Список неизвестен (чтение сорвалось или не дошло до конца) — читаются
  все, как прежде.
- [x] Запрет Telegram на розыск по нику пишется одной строкой со сроком, без
  трассировки. Обрыв розыска для всех оставшихся не заведён: розыск по нику в
  догоне остаётся только при неизвестном списке, а неполного чтения журнал не
  видел ни разу — защита от не встреченного края (правило 18). Архивные
  переписки: запрос списка без папки по протоколу отдаёт и архив — по
  описанию параметра, живой проверки не было.

## 2. Мёртвый канал не опрашивается вечно

`@python_vakansii1` отвечает «ника нет» (канал удалён или переименован), а
опрашивается дважды за круг и тратит тот же лимит поиска по нику.

- [x] Канал, которого больше нет (ник никем не занят), выключается и больше
  не опрашивается; причина — строкой в журнале.
- [x] Сводка названий по такому каналу пишет одну строку, без трассировки.
  Сама сводка по-прежнему идёт и по выключенным каналам — так решено в коде
  ради свежих названий в окне; мёртвый канал стоит ей одного обращения за круг.

## 3. Посты после простоя не теряются

Догон канала читает не больше `backfill_limit` свежих постов и переносит
отметку на самый свежий, хотя прежняя не встретилась: середина пропадает.

- [x] Отметка сдвигается только по прочитанному: за круг берутся старейшие
  непрочитанные, остальное — следующими кругами. Первый обход канала (без
  отметки) берёт, как прежде, предел самых свежих.

## 4. Сервер инструментов агента гасится целиком

`force_exit` не даёт приложению сервера закрыться: задачи копятся до закрытия
окна, при выходе — ложные ERROR.

- [x] Сервер гасится вместе с приложением: висящие вызовы гасит сам uvicorn
  по сроку мягкой остановки, и остановка приложения не пропускается.

# План: автоотклик с подтверждением

**Цель:** третье положение автоотклика — перед каждой отправкой введённых
данных откликатель ждёт человека: окно с пунктами «вопрос — ответ», правка,
«Подтвердить» или «Закончить».

**Устройство:** одно ожидание человека (`backend/agent/human_gate.py`) учится
нести данные туда и обратно; капча и вход — то же ожидание без данных. Его
зовут все способы отклика через одну точку подтверждения
(`backend/applying/confirm.py`): Telegram и почта — перед отправкой письма,
агент — инструментом подтверждения страницы. Ввод агента в этом режиме
пропускает только подтверждённое. Окно — рамка большого окна; свёрнутое —
плашка нижней полосы той же цепочки, что у капчи.

**Спека:** `docs/specs/14.10.2026 автоотклик с подтверждением.md`.

**Порядок работы:** слайс за слайсом — тесты до кода и красными, код, весь набор
зелёным, карты, ревью отдельными агентами (ошибки, манифест, дубликаты, тесты),
правки, коммит. Окно показывается человеку после слайса 5. После всех слайсов —
полное ревью. Мутаций нет.

Тесты питона: `pipenv run python -m pytest <файлы> -q -p no:cacheprovider`.
Тесты фронта: `cd client/web && npx vitest run <файл>`.

## Общие условия

- Переиспользуется всё по таблице спеки: ожидание человека, цепочка
  `human_needed` / `human_resolved` → плашка → `system.human_done`, плашка
  `HumanPlate`, рамка `ModalShell`, `ScreeningPair`, приём перечня
  `letter_writer`, исходы `applying/result.py`, место
  прогона. Новое — только там, где готового нет.
- Пункт подтверждения один на все способы: `{label, kind, value, error}`, где
  `kind` — `text` (поле и письмо), `choice` (список, переключатель — значение
  текстом), `check` (галочка — `true`/`false`); `error` — текст ошибки поля с
  сайта при повторном показе, иначе пусто; у пунктов агента ещё `selector`.
  Письмо — пункт `text` без подписи, тема письма — пункт `text` с подписью
  «Тема». Для схемы инструмента пункт — свой `TypedDict` рядом со
  `ScreeningPair`, а не она: у пары ответ непустой по схеме, а пункт по спеке
  бывает пустым. В запись скрининга пункты с подписью переводятся в те же пары.
- Исход задачи агента окончательный, когда он `Applied` или `Dropped`: один
  кортеж в `jobs.py` вместо нынешних трёх проверок на `Applied` в `finish`,
  `report_failure` и `record_application` — после «Закончить» агент не
  перепишет исход ни неудачей, ни откликом.
- «Закончить» в этом прогоне не повторяется само: прогон идёт по списку один
  раз, а передача берёт только вакансии своего разбора (`hand_over` → `stored`
  этого разбора) — учёта не нужно.
- Истёкший срок подтверждения обрывает весь прогон — как у капчи.
- Режимы «выкл» и «вкл» работают ровно как сейчас.
- Тексты окна — на «вы», без жаргона.

## Что проверить в ревью

- «Стоп» во время ожидания подтверждения гасит его сразу, как на капче, и
  ничего не уходит.
- Истёкший срок подтверждения обрывает весь прогон, как у капчи.
- Сайт отверг поле — окно показывается снова с правками человека и
  подсвеченной ошибкой, а не с ответами модели.
- Агент вписывает текст, не совпадающий с подтверждённым, или в чужое поле —
  отказ, на страницу не попадает.
- Страница сменилась за время ожидания — её поля не подтверждены (ключ —
  адрес страницы и селектор), ввод отклоняется, агент подтверждает заново.
- Человек поправил ответ — уходит и записывается в скрининг/отклик правленый.
- Пустое поле, которое человек так и оставил пустым, — уходит пустым, отклик
  не обрывается приложением.

## Слайс 4. Агент: подтверждение страницы и строгий ввод

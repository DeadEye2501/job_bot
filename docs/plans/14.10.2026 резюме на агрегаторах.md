# План: резюме на агрегаторах

**Цель:** приложение знает резюме человека на каждом агрегаторе и откликается
только тем, которое человек выбрал.

**Устройство:** таблица `aggregator_resume` (её заводит общая миграция плана
«новые поля профиля») — зеркало сайта. Одна функция репозитория записывает
любое изменение списка: сверку со сканом и удаление пропавшего. Сканирование —
своя задача агента со своим инструментом отчёта; идёт следом за входом и по
пункту «Обновить резюме» в меню карточки. Отметку «откликаться этим» ставят только человек и
автозаполнение. Откликатель получает отмеченное резюме в задании; без
отмеченного кнопка агрегатора не предлагается; пропажа отмеченного — новая
причина остановки всего прогона.

**Спека:** `docs/specs/14.10.2026 резюме на агрегаторах.md`.

**Порядок работы:** слайс за слайсом — тесты до кода и красными, код, весь набор
зелёным, карты, ревью отдельными агентами (ошибки, манифест, дубликаты, тесты),
правки, коммит. Окно показывается человеку после слайса 4. После всех слайсов —
полное ревью. Мутаций нет.

Тесты питона: `pipenv run python -m pytest <файлы> -q -p no:cacheprovider`.
Тесты фронта: `cd client/web && npx vitest run <файл>`.

## Общие условия

- Миграций в этом плане нет: таблица, индексы и `Aggregator.can_add_resume`
  уже заведены слайсом 1 плана «новые поля профиля».
- Отметку ставят только человек (кружок) и автозаполнение (план «автозаполнение
  резюме»). Сканирование, удаление, вход — никогда.
- Строку «Поиск по сети» всё это не касается.
- Зов моста пишется литералом, не тернарием в `_launch`.
- Тексты окна — на «вы», без жаргона.

## Что проверить в ревью

- Пересканирование, где на сайте поменялись все резюме: старые записи ушли,
  новые пришли без отметки, отклик через агрегатор недоступен до выбора.
- Резюме с той же ссылкой после сканирования — та же запись, та же отметка.
- Удаление агрегатора удаляет его резюме.
- Отмеченное резюме пропало посреди «откликнуться на все новые» — прогон
  остановлен целиком, Telegram и почта следующих вакансий не тронуты, плашка
  с причиной.
- Агрегатор без входа: пункт «Обновить резюме» в меню неактивен.

## Слайс 1. Репозиторий резюме

**Файлы:**
- Создать: `backend/repository/aggregator_resumes.py` — дело «резюме агрегатора
  в базе»; отличие от `aggregators.py` — своя таблица и своя сверка:
  - `resumes_of(session, aggregator_id) -> list[AggregatorResume]` в порядке
    `position`;
  - `sync_resumes(session, aggregator_id, seen: list[SeenResume], can_add:
    bool)` — сверка по ссылке: совпавшие — название и место переписаны,
    отметка не тронута; новые добавлены без отметки; пропавшие удалены;
    `Aggregator.can_add_resume = can_add`;
  - `choose_resume(session, aggregator_id, resume_id)` — отметка этого, снятие
    с прежнего в одной транзакции;
  - `drop_resume(session, resume_id)` — удаление; другое не отмечается;
  - `chosen_resume(session, aggregator_id) -> AggregatorResume | None`.
- Изменить: `backend/payloads.py` — `SeenResume(title: str, url: str)`; порядок
  — порядок списка.
- Изменить: `backend/repository/aggregators.py` — `delete_aggregator` удаляет и
  его резюме, тем же путём, каким чистит прочие ссылки.
- Тесты: `tests/backend/test_repository_aggregator_resumes.py`.

**Даёт:** функции выше; `SeenResume`.

- [x] Тесты: первое сканирование добавляет все без отметки; повторное с той же
  ссылкой и новым названием — та же запись (тот же `id`), отметка цела;
  пропавшее удалено вместе с отметкой, другое не отмечено; порядок — порядок
  сайта; `choose_resume` переносит отметку; `can_add` пишется; удаление
  агрегатора уносит его резюме.
- [x] Красные; код; зелёные; весь набор; карты; ревью; коммит.

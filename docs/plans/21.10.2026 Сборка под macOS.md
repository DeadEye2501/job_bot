# План: сборка под macOS

**Цель:** `JobBot.app` для Apple Silicon, собранный на GitHub Actions, рядом с
нынешней Windows-сборкой. Для Windows не меняется ничего: тот же код
исполняется, те же зависимости ставятся, `JobBot.spec` собирает exe из тех же
модулей.

**Устройство:** как в спеке, двойники лежат рядом с Windows-модулями.
Выбор по `sys.platform` делается один раз на каждый предмет, в том месте, где
Windows-код уже живёт.

Правка существующего файла — это вставка ветки `if sys.platform == "darwin":`
перед прежним кодом. Прежние строки не меняются и не переезжают, поэтому на
Windows исполняется ровно то, что исполнялось.

Двойник в ветке грузится по имени строкой — `importlib.import_module(
"adapters.process_macos")`, а не оператором `import`. Оператор `import`
modulegraph PyInstaller видит и внутри `if`, и тогда мак-модули попали бы в
Windows-exe. Строку он не видит, поэтому exe собирается из прежнего набора
модулей. Мак-spec называет двойников в `hiddenimports` по той же причине.

Не трогаются `Pipfile`, `Pipfile.lock`, `JobBot.spec` и всё в `tests/`.
Маркеры в `Pipfile` потребовали бы пересборки lock на Windows, а та сдвинула бы
незакреплённые транзитивные зависимости. Поэтому у мака свой `macos/Pipfile` и
свой `JobBot-macos.spec`.

**Спека:** `docs/specs/20.10.2026 Сборка под macOS.md`.

**Допуск на правку** (слово человека 21.10.2026): существующее править немного
и только так, чтобы для Windows ничего не сломалось и не изменилось.

**Чем план расходится со спекой:**
- **Зависимости мака** — в своём `macos/Pipfile`, а не маркерами в общем
  (обоснование выше).
- **Подмена двух модулей.** `adapters.process_windows` и
  `adapters.app_tied_process` вызывающие импортируют по имени в четырёх местах
  (`browser.py:14-15,216`, `claude_code_process.py:25`). Поэтому выбор для них
  — не у вызывающих, а в `adapters/__init__.py`: на маке оба имени пакета (и
  атрибут пакета, и запись в `sys.modules`) указывают на двойников. Читатель
  `browser.py` видит Windows-имя — это объясняет комментарий в `__init__.py`.
  Плата за то, что четыре строки импорта остаются нетронутыми.
- **Сторож дочерних процессов** — свой процесс, который ловит конец трубы, а не
  своя группа и kqueue `NOTE_EXIT`. Труба закрывается и при `kill -9`, так что
  предел спеки «нет гарантии при kill -9» снимается.
  - Гасит он дерево: привязанные процессы и всех их потомков на момент конца,
    сразу `SIGKILL`, как `TerminateJobObject` у Windows.
  - Процесс он узнаёт по паре «pid + время старта», чтобы не погасить чужой
    процесс, получивший тот же номер.
- **Поиск Claude Code** не дублируется. На маке `main.py` дописывает в конец
  `PATH` известные места установки, и `shutil.which("claude")`
  (`adapters/claude_code.py:56`) находит его сам. Заодно находится `node` из
  `/opt/homebrew/bin`, нужный npm-обёртке.
- **Самообновления в первой мак-версии нет** (спека это допускает): `updatable`
  на маке `False`, и `BottomBar.svelte:113` закрывает обновление. Кнопка при
  найденной версии видна, но заперта.
- **Тесты.** Спека велела пометить Windows-тесты платформой, а это правка
  `tests/`. Вместо этого:
  - тесты двойников лежат в `macos/tests/` со своим `conftest.py`;
  - на маке гоняется только этот набор;
  - набор `tests/` на маке не гоняется вовсе: его `conftest.py` сторожит
    каталог данных через `APPDATA`, а `config.py:21-22` на маке её не читает,
    и сторож (`tests/conftest.py:105-131`) падает перед каждым тестом;
  - общий код на маке проверяется прогоном собранного приложения (слайс 5) и
    проверкой вживую.
- **Шрифты** (п. 16) не правятся. `base.css:62` начинается с `'Segoe UI'`,
  которого на маке нет, дальше идут `system-ui` и `-apple-system`, то есть SF.
  Моноширинные стеки начинаются с `ui-monospace`, то есть SF Mono. Остаётся
  проверка вживую.

**Порядок работы:** ветка `macos-build`, слайс за слайсом без пауз. На слайс:
- тесты до кода;
- красный прогон;
- код;
- зелёный прогон;
- весь Windows-набор;
- ревью;
- коммит.

После всех слайсов — полное ревью.

Чистые части двойников тестируются и на Windows через фейки. Части с
Quartz/AppKit/`ps`/сигналами помечены
`pytest.mark.skipif(sys.platform != "darwin", reason="только macOS")`.
Свою красную и зелёную фазу они проходят на мак-раннере: коммит с тестами →
push ветки → прогон workflow красный → коммит с кодом → push → прогон зелёный.

**Push ветки `macos-build` нужен на каждом слайсе.** Человек разрешил эти push
на весь план 21.10.2026; push в `main` по-прежнему только по его слову.

Команды:
- тесты двойников: `pipenv run python -m pytest macos/tests -q -p no:cacheprovider`;
- Windows-набор: `pipenv run python -m pytest -q -p no:cacheprovider`.

## Общие условия

- **Windows не задет.** Перед первым слайсом записать счёт Windows-набора.
  После каждого слайса Windows-набор зелёный тем же счётом: тесты двойников
  в него не входят (`testpaths = ["tests"]`).
- **Дифф существующих файлов** (`git diff -- . ':!docs'`) состоит из
  добавленных строк `+`: ветки `darwin` и `import importlib`/`import sys`, где
  их нет. Строки `-` допустимы ровно в четырёх местах; на Windows каждое даёт
  прежнее значение:
  - `backend/single_instance.py:38` — имя из `errno`;
  - `client/bridge/app_update.py:33` — к `updatable` дописано
    `and sys.platform != "darwin"`;
  - докстроки `open_in_system` и `_show_in_folder` в `client/bridge/desktop.py`,
    которые с мак-веткой стали бы ложными: «startfile есть только на Windows» и
    «единственный в мосте запуск чужой программы».
- **Двойник грузится строкой** (`importlib.import_module`), а не оператором
  `import`. Всякий новый двойник вписывается в `hiddenimports`
  `JobBot-macos.spec` в том же слайсе.
- **Двойник повторяет подпись функции, которую заменяет.** Имя повторяет у
  публичных функций. Двойник приватной функции (`_show_in_folder`,
  `_unlock_frame`) публичен, без подчёркивания: его зовёт другой модуль.
- Базовых классов и реестров нет.
- **Двойники журнал пишут через `logger.exception`, как оригиналы.** Сторож
  (`--tie-watch`) журнал не пишет вовсе: он ввозит `main.py` с его журналом
  (`main.py:73-86`, открытие отложено), и пока он молчит, файл не открывается
  вторым процессом.
- Python 3.13 arm64, раннер `macos-14`; Intel-маки не поддерживаются.
- Подписи Apple нет; первый запуск — правый клик → «Открыть» или
  `xattr -cr JobBot.app`.

## Внимание ревью

- **Скудный `PATH`.** Приложение из Finder получает
  `/usr/bin:/bin:/usr/sbin:/sbin`, а Claude Code из `~/.local/bin` должен
  находиться. Тест в слайсе 2.
- **Свёрнутое окно.** Человек свернул окно входа или ушёл на другой рабочий
  стол — вход не должен закончиться. Тест в слайсе 1, проверка вживую в
  слайсе 6.
- **Чужой процесс.** Сторож не трогает процесс, получивший номер вышедшего
  привязанного. Тест в слайсе 1.
- **Сироты.** После выхода или `kill -9` JobBot не остаётся ни потомков
  браузера под драйвером, ни MCP-процессов Claude Code. Тест в слайсе 1,
  проверка вживую в слайсе 6.
- **Сбой при старте** доходит до человека окном, и текст с кавычками скрипт
  показа не ломает. Тест в слайсе 4.

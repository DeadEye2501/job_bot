# Сбор и отклик: план реализации

> **Для исполнителя:** работа идёт слайсами по скиллу `free-hands:keeping-code-clean`:
> тест до кода и виден красным → код → карты → ревью агентами через
> `superpowers:requesting-code-review` → правки → коммит. План — он же
> роадмапа: слайсы и шаги отмечаются галочками прямо здесь, заметки по ходу
> пишутся под слайсом.

**Цель:** сбор вакансий и отклик на них — два изолированных потока. Сбор
выносит вердикт и отдаёт id; откликатель откликается на каждую первым
доступным способом — Telegram, кнопка агрегатора, форма, почта, — не зная,
откуда вакансия, и ничего не проверяя.

**Устройство.**
1. **Воронка** (`backend/domain/transitions.py`,
   `backend/repository/vacancy_status.py`) — единственная, кто двигает статус.
2. **Способы** (`backend/domain/apply_order.py`) — чистая функция
   `apply_ways(vacancy, world)`: факты о вакансии и о мире → упорядоченный
   перечень.
3. **Откликатель** (`backend/applying/`) — цикл по id и исполнители способов.
   Модулей источников не импортирует.
4. **Сбор** (`backend/flows/`) — разбор отдаёт итог, `handover` решает
   «откликаться» и зовёт откликателя через `pipeline.apply`.
5. **Бот** (`backend/bot/`) — работа на месте прогона держит набор агента;
   оборот — одна задача.

**Стек:** Python 3.13, SQLAlchemy 2 async, Alembic на SQLite, Pyrogram,
Playwright, Svelte 5 + vitest.

**Спека:** `docs/specs/10.10.2026 Сбор и отклик.md`

## Глобальные ограничения

- Питон: `pipenv run python -m pytest <путь> -q`. Фронт: `npm test` в
  `client/web`.
- Файл — не больше 500 строк, функция — не больше 40 строк, 3 уровней
  вложенности и 4 параметров.
- Широкий `except` — только с `logger.exception` или пробросом.
- Манифест, правила 17 и 18: решение принимается в одном месте, ниже по
  потоку не перепроверяется; сторожей и защит от краёв не заводить.
- Тексты окну — на «вы», без транслита.
- Комментарии — только довод, без летописи.
- «Коммит» — `git add . && git commit`; сообщение кончается строкой
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Живой прогон и сборка exe в план не входят: их делает человек после.

## Решения плана, которых нет в спеке

- **Набор агента — на работу места прогона.** `agent_work` ставит `bot.kit` на
  время работы; `pipeline.apply` зовёт откликателя с ним. Поиск и отклик делят
  один браузер: два браузера на один профиль Chromium не открывает.
- **Догон переписки нового HR** идёт после передачи откликателю: иначе догон
  положил бы наше же письмо в переписку без вакансии. Разбор отдаёт нового HR
  в итоге, `handover` заводит догон после отклика.
- **Telegram пишется без `Bot.send`.** Исполнитель зовёт
  `adapters.telegram.send_dm` на `pipeline.client` напрямую; `bot/send.py`
  уходит целиком — других зовущих у него нет.
- **Событие отклика одно — `applied`.** Миграция переименовывает
  `applied_elsewhere` в `applied` и удаляет строки `auto_send`, `apply_failed`,
  `vacancy_closed`, `applied_sent`.
- **Telegram в `ApplicationVia`** — правкой строки перечисления в миграции
  `a9c3e1f07b42`, как с аватаром агрегатора: SQLite ограничения на значения не
  держит, живая база новое значение примет.
- **Окно без отказа «агент заперт».** Мост отдаёт только доступные способы;
  способов нет — «Откликнуться некуда: нет доступных способов».

## Где смотреть при ревью

1. Вакансия из канала с одной почтой, почта настроена. Ждём письмо, строку
   `application` с `email`, Applied, событие `applied` (задачи 5, 7).
2. У вакансии HR в Telegram и почта; Telegram отдаёт FloodWait. Ждём письмо
   почтой той же вакансии, запрет в `flood_wait_until_ts`, и у следующей
   вакансии прогона Telegram в перечне нет (задачи 3, 4).
3. Обход агрегатора нашёл пять вакансий, две с HR в Telegram. Ждём, что за
   время поиска ни одного отклика не ушло, а после разбора пула ушли все пять
   по порядку (задача 8).
4. Человек нажал «Откликнуться» на Decline и выбрал почту; почта не приняла.
   Ждём отказ без перехода к другим способам, статус Decline (задачи 3, 10).
5. «Прогнать заново» на Applied, вердикт «годна». Ждём New и новый отклик
   (задача 7).

```python
# backend/domain/transitions.py
# Откуда отклик проводит вакансию в Applied: отклика ещё не было или с
# вакансией попрощались. Дальше по воронке отклик — реплика переписки, и
# статус он не трогает. Кто откликнулся, правило не знает.
APPLY_MOVES_FROM: frozenset[VacancyStatus] = frozenset({
    VacancyStatus.NEW, VacancyStatus.NOT_FIT, VacancyStatus.SCAM,
    VacancyStatus.GHOSTING, VacancyStatus.DECLINE,
})


def should_apply_status(current: VacancyStatus, new: VacancyStatus) -> bool:
    """Гейт авто-перехода по графу: ответ HR и таймер молчания."""
    return new in ALLOWED_AUTO_TRANSITIONS[current]
```

```python
# backend/repository/vacancy_status.py
async def mark_vacancy_applied(
    session: AsyncSession, vacancy_id: int, explanation: str | None
) -> bool:
    """Отклик состоялся: Applied из `APPLY_MOVES_FROM`, остальное не трогается.

    Отвечает, сменился ли статус; смена пишется в историю. Транзакцию
    закрывает зовущий.
    """
    vacancy = await session.get(Vacancy, vacancy_id)
    if vacancy is None or vacancy.status not in APPLY_MOVES_FROM:
        return False
    session.add(_move_status(vacancy, VacancyStatus.APPLIED, _Signature(explanation)))
    return True
```

```python
"""Цикл откликателя: по каждой вакансии первый доступный способ, пока один не удастся."""

EXECUTORS: dict[str, Executor] = {}


async def apply_vacancies(kit: AgentKit, vacancy_ids: list[int]) -> None:
    """Откликнуться на каждую по очереди. Мир читается раз и доучивается по ходу."""
    world = await read_world(kit)
    total = len(vacancy_ids)
    for number, vacancy_id in enumerate(vacancy_ids):
        kit.pipeline.emit_progress("apply", await _title(kit, vacancy_id), number, total)
        await _apply_one(kit, world, vacancy_id)


async def apply_chosen(kit: AgentKit, vacancy_id: int, way: Way) -> Outcome:
    """Ручной отклик: перечень — один выбранный способ."""
    outcome = await EXECUTORS[way.method](kit, vacancy_id, way)
    _log_missed(vacancy_id, way, outcome)
    return outcome


async def _apply_one(kit: AgentKit, world: World, vacancy_id: int) -> None:
    tried: set[Way] = set()
    while True:
        ways = [w for w in await ways_in(kit, world, vacancy_id) if w not in tried]
        if not ways:
            return
        way = ways[0]
        tried.add(way)
        outcome = await EXECUTORS[way.method](kit, vacancy_id, way)
        if outcome == "applied":
            return
        _log_missed(vacancy_id, way, outcome)
        if outcome.lesson is not None:
            learn(world, outcome.lesson)
```

`ways_in(kit, world, vacancy_id)` — в `world.py`: факты вакансии одним
чтением и `apply_ways(facts, world)`; удалённая вакансия — пустой перечень.
`available_ways(kit, vacancy_id)` — то же со свежим `read_world` (для окна).

`read_world`: `telegram_open = rs.flood_wait_until_ts <= time.time()`,
`mail_ready = await get_mail_account(session) is not None`,
`agent_ready = current_refusal(rs.chat) is None`, `sites` — `KnownSite` по
`list_aggregators`, `closed_sites = set()`.

`vacancy_facts`: `hr_handle` — `@ник` HR, иначе `str(telegram_user_id)`, иначе
пусто (HR без адреса — не способ); `source_site` — `KnownSite` агрегатора
`vacancy.source_aggregator_id`; `contacts` — `contact_values(session, id)`.
Перенос из `vacancy_ways` без фильтра отсева.

`learn`: `TelegramClosed` → `world.telegram_open = False`; `SiteClosed` →
`world.closed_sites.add(site_id)`.

`_log_missed` — `logger.info("отклик на вакансию %d способом %s не удался: %s", ...)`.

```python
# backend/flows/handover.py
"""Передача отобранного откликателю: решение «откликаться» и догон новых HR после отклика."""


async def to_apply(session_factory, vacancy_ids: list[int]) -> list[int]:
    """Откликаться — значит после вердикта вакансия стоит в New."""
    if not vacancy_ids:
        return []
    async with session_factory() as session:
        rows = await session.scalars(select(Vacancy.id).where(
            Vacancy.id.in_(vacancy_ids), Vacancy.status == VacancyStatus.NEW))
        chosen = set(rows)
    return [vacancy_id for vacancy_id in vacancy_ids if vacancy_id in chosen]


async def hand_over(pipeline, judged: list[tuple[int, Judged]]) -> None:
    """Отклик раньше догона: догон, пошедший первым, положил бы наше письмо
    в переписку без вакансии."""
    chosen = await to_apply(pipeline.session_factory,
                            [vacancy_id for vacancy_id, one in judged if one.stored])
    if chosen:
        await pipeline.apply(chosen)
    for _, one in judged:
        if one.fresh_hr is not None:
            spawn_hr_backfill(pipeline, one.fresh_hr)


async def judge_and_hand_over(pipeline, vacancy_id, text, channel_username,
                              *, allow_delete: bool = True) -> bool:
    """Разбор одной вакансии и передача её итога; ответ — записан ли исход."""
    judged = await parse.parse_and_update_vacancy(
        pipeline, vacancy_id, text, channel_username, allow_delete=allow_delete)
    await hand_over(pipeline, [(vacancy_id, judged)])
    return judged.stored
```

```python
# backend/bot/turn.py
def launch_turn(bot, label: str) -> asyncio.Task | None:
    """Оборот одной задачей: недоразобранное, каналы, агрегаторы. Пусто — место занято."""

    async def turn(kit: AgentKit) -> str:
        await _recover(bot)
        await bot.ingestion.poll_active_channels()
        await aggregators.seek_all(bot, kit)
        return "ok"

    if not slot.launch_in_slot(bot, lambda: work.agent_work(bot, turn), label):
        return None
    return bot.launched_task
```

`aggregators.seek_all(bot, kit)` — бывшее тело `aggregator_round`: выход,

`run_aggregator_now` зовёт `seek_source` под `agent_work`, как сейчас.
`force_poll_once`: задача пуста → `"busy"`; иначе `outcome, _ = await task`

пройдены.» (`client/bridge/system.py`, `RUN_REFUSALS` в
`client/bridge/refusals.py`).

`agent_work`: `bot.kit = _kit(bot)`, `gate.reset()`; в `finally` —

# Агрегаторы — данные: план реализации

> **Для исполнителя:** работа идёт слайсами по скиллу `free-hands:keeping-code-clean`:
> тест до кода и виден красным → код → карты → ревью агентами через
> `superpowers:requesting-code-review` → правки → коммит. Шаги отмечаются
> галочками (`- [ ]`).

**Цель:** схема базы под агрегаторы и то, что в коде обязано поменяться вместе
с ней: контакты вакансии отдельной таблицей, отметка о мусоре с агрегатора,
шесть новых полей анкеты, три новые настройки.

**Устройство:** одна схемная ревизия Alembic после `init` заводит все новые
таблицы и колонки и строку «Поиск по сети». Правило нормальной формы контакта
живёт одной функцией домена. Разбор вакансии пишет контакт в `vacancy_contact`
вместо заметок. Фронта в плане нет: окно (блок контактов в карточке, поля
анкеты, поля настроек) — `docs/specs/09.10.2026 Агрегаторы — окно.md`. Здесь
только мост.

**Стек:** Python 3, SQLAlchemy 2 (async, aiosqlite), Alembic 1.18.4, SQLite с
`PRAGMA foreign_keys=ON` (`adapters/db.py:47`), pytest + pytest-asyncio.

**Спека:** `docs/specs/09.10.2026 Агрегаторы — данные.md`

## Глобальные ограничения

- Тесты гоняются так: `pipenv run python -m pytest <путь> -q`.
- Файл — не больше 500 строк, функция — не больше 40 строк и 4 параметров. Хук
  отклоняет запись сверх этого.
- Комментарии и докстроки — только довод. Ни дат, ни пересказа инцидента.
- Тексты, которые мост отдаёт окну, — на «вы», без транслита.
- Удаление агрегатора устроено как удаление канала: ссылки на него у
  вакансий, откликов и отметок о мусоре обнуляет код удаления
  (`delete_aggregator`, план потока, задача 3), как `delete_channel` обнуляет
  ссылки на канал. Правила `ON DELETE SET NULL` в базе нет — по слову
  человека, вопреки строке спеки «на всех трёх ссылках стоит `ON DELETE SET NULL`».
- Колонки с внешним ключом добавляются в SQLite с `inline_references=True`.
  Составная уникальность — уникальным индексом: `Index(..., unique=True)`.
- `JobBot.spec` перечисляет миграции поимённо. Новая ревизия добавляется в `datas`.
- «Коммит» — это `git add . && git commit`. До и после коммита проверить, что
  `docs/seed/` и личные данные в git не попали: `git status --short`,
  `git show --stat HEAD`.
- Сообщение коммита кончается строкой
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Карты пересобираются из корня репозитория:
  `python "C:/Users/deade/.claude/skills/free-hands/skills/keeping-code-clean/tools/module_map.py"`.

## Что сюда не вошло и почему

У следующих пунктов спеки нет потребителя до плана потока
(`docs/plans/09.10.2026 Агрегаторы — поток.md`). Код без потребителя запрещён
правилом 8 манифеста. Схема под них заводится здесь (задача 1), а код — там:

- заведение агрегатора (хост в нормальной форме, отказ пустому адресу),
  удаление с подтверждением по числу откликов, неудаляемость «Поиска по сети»
  — поток, задача 3;
- каталог `browser/<id>/`, его место в `config.data_dirs()` и снос при удалении
  агрегатора — поток, задачи 5 и 17;
- `host_owns` и выемка `source_key` из адреса страницы — поток, задача 2.
  Пишутся там в `backend/domain/hosts.py` поверх `address_parts`: перенос
  `normalize_host` и разбор адреса делает задача 2 этого плана;
- `is_known` — поток, задача 7. Здесь отметка о мусоре только учится новым
  колонкам, а проверка «номер на агрегаторе уже отмечен мусором» становится
  публичной `source_trashed` (задача 7 этого плана): поток её зовёт, а не пишет
  второй запрос;
- контакты, найденные искателем, — поток, задача 7. Пишутся той же
  `add_contact` (задача 3 этого плана) с `ContactAddedBy.AGENT`;
- запись `application` и `screening` — поток, задача 8. Здесь — только их
  удаление вместе с вакансией (задача 4);
- `mail_account`: чтение и запись, шифрование пароля, вымарывание пароля в
  журнале — поток, задача 4;
- фикстура строки «Поиск по сети» для тестов — поток, задача 3.

Статистика здесь не меняется: вакансии и мусор без `source_channel_id` уже
попадают в строку «Без канала» (`stats_pipeline._ingest_by_channel`, внешнее
соединение по каналу).

## Где смотреть при ревью

Пять случаев, о которых спека молчит, но на которых человек споткнётся первым.
Каждый закреплён тестом в своей задаче.

1. Разбор нашёл тот же контакт, что человек уже добавил руками, в другом
   регистре. Ждём одну строку, и она остаётся человеческой (задача 3).
2. Одна ссылка с `utm_*`, `from` и косой чертой в конце и без них. Ждём один
   `match_key` (задача 2).
3. Повторный разбор резюме, где нет зарплаты и пола. Ждём, что введённые
   человеком значения остаются (задача 8).
4. Удаление агрегатора, на который ссылаются вакансия, отклик и отметка
   о мусоре. Ждём, что три ссылки обнулены, а строки живы — как при удалении
   канала (план потока, задача 3).
5. «Прогнать заново» у вакансии с заметкой человека. Ждём, что заметка не
   тронута (задача 3).

```python
"""Хост адреса в нормальной форме и остальные части адреса."""

from typing import NamedTuple
from urllib.parse import urlsplit

from backend.domain.company_names import ADDRESS_START_RE


class AddressParts(NamedTuple):
    host: str
    path: str
    query: str
    fragment: str


def address_parts(url: str) -> AddressParts:
    """Адрес по частям: хост, путь без косых черт по краям, параметры и якорь.

    Хост даёт `normalize_host`, а не `urlsplit`: тот оставил бы порт,
    завершающую точку и регистр, и одна ссылка получила бы два хоста.
    """
    text = ADDRESS_START_RE.sub("", url.strip()).lstrip("/")
    try:
        parts = urlsplit("//" + text)
    except ValueError:
        # Непарную «[» urlsplit принимает за начало адреса IPv6 и бросает. Контакт
        # из текста вакансии бывает каким угодно, а запись разбора из-за него
        # падать не должна: путь — всё после хоста, как есть.
        return AddressParts(normalize_host(url), text.partition("/")[2].strip("/"), "", "")
    return AddressParts(
        normalize_host(url), parts.path.strip("/"), parts.query, parts.fragment
    )
```

```python
"""Нормальная форма контакта вакансии, по которой два написания признаются одним."""

import re
from urllib.parse import parse_qsl, urlencode

from backend.domain.hosts import address_parts

EMAIL_PATTERN = r"[^\s@]+@[^\s@]+\.[a-zA-Z]{2,}"
PHONE_PATTERN = r"\+?\d[\d\s()-]{7,}\d"
"""Почта и телефон, без якорей. По ним же разбор поста ищет адрес внутри строки
(`backend/llm/vacancy.py`): что считать почтой и телефоном, решает одно правило."""

_MAILTO = "mailto:"
_ADDRESS_RE = re.compile(EMAIL_PATTERN)
_PHONE_RE = re.compile(PHONE_PATTERN)
_ARRIVAL_MARKS = ("utm_",)
_ARRIVAL_PARAMS = frozenset({"from"})


def contact_key(value: str) -> str:
    """Почта — без регистра и `mailto:`, телефон — одни цифры, ссылка — хост по
    правилу `normalize_host`, путь без косой черты в конце, без меток прихода."""
    text = value.strip().lower()
    if text.startswith(_MAILTO):
        text = text[len(_MAILTO):]
    if _ADDRESS_RE.fullmatch(text):
        return text
    if _PHONE_RE.fullmatch(text):
        return re.sub(r"\D", "", text)
    return _link_key(text)


def _link_key(text: str) -> str:
    parts = address_parts(text)
    kept = [
        (name, value)
        for name, value in parse_qsl(parts.query, keep_blank_values=True)
        if name not in _ARRIVAL_PARAMS and not name.startswith(_ARRIVAL_MARKS)
    ]
    path = f"/{parts.path}" if parts.path else ""
    query = f"?{urlencode(kept)}" if kept else ""
    fragment = f"#{parts.fragment}" if parts.fragment else ""
    return parts.host + path + query + fragment
```

```python
async def record_trash_event(
    session: AsyncSession, vacancy: Vacancy | None, reason: str | None
) -> None:
    """Отметить объявление мусором. Одно объявление — одна отметка.

    Объявление узнают по номеру на источнике: по номеру сообщения в канале или
    по номеру на агрегаторе. Без номера сверить не с чем, и отметка пишется всегда.
    """
    mark = TrashEvent(reason=reason)
    if vacancy is not None:
        mark.source_channel_id = vacancy.source_channel_id
        mark.source_msg_id = vacancy.source_msg_id
        mark.source_aggregator_id = vacancy.source_aggregator_id
        mark.source_key = vacancy.source_key
    if not await _trash_noted(session, mark):
        session.add(mark)


async def source_trashed(session: AsyncSession, aggregator_id: int, key: str) -> bool:
    """Отмечено ли мусором объявление с этим номером на этом агрегаторе."""
    return await _marked(
        session,
        TrashEvent.source_aggregator_id == aggregator_id,
        TrashEvent.source_key == key,
    )


async def _trash_noted(session: AsyncSession, mark: TrashEvent) -> bool:
    """Отмечено ли это объявление мусором раньше."""
    if mark.source_key is not None:
        return await source_trashed(session, mark.source_aggregator_id, mark.source_key)
    if mark.source_msg_id is None:
        return False
    return await _marked(
        session,
        TrashEvent.source_channel_id == mark.source_channel_id,
        TrashEvent.source_msg_id == mark.source_msg_id,
    )


async def _marked(session: AsyncSession, *same) -> bool:
    return (await session.scalar(select(TrashEvent.id).where(*same).limit(1))) is not None
```

```python
def decrypt_or_none(ciphertext: str | bytes | None, what: str) -> str | None:
    """Открытый текст секрета, а нечитаемый шифротекст — `None`, «не настроено».

    Связка ключей ОС и база разъезжаются при чистке связки, переносе профиля и
    восстановлении из копии, а брошенный отсюда отказ не ловит никто:
    приложение падало бы раньше окна, где секрет вписывают заново. Чужой ключ
    даёт `InvalidToken`, испорченная запись — `ValueError`; следствие у них одно.

    Секрета нет вовсе — пустая строка: читать нечего, и беды в этом нет.
    """
    if not ciphertext:
        return ""
    try:
        return _cipher().decrypt(ciphertext).decode("utf-8")
    except (InvalidToken, ValueError):
        logger.exception("%s is unreadable, treating as unset", what)
        return None
```

Fernet принимает токен и строкой, и байтами, поэтому запись сеанса Telegram
(`LargeBinary`) идёт той же функцией.

```python
"""Разовый перенос «Контакты: …» из заметок в vacancy_contact."""

import os
import sqlite3
import sys

sys.path.insert(0, sys.argv[1])
from backend.domain.contact_keys import contact_key  # noqa: E402 — корень проекта известен только из довода

PREFIX = "Контакты: "
db = sqlite3.connect(os.path.expandvars(r"%APPDATA%\JobBot\jobbot.db"))
db.execute("PRAGMA foreign_keys=ON")
moved = skipped = 0
for vacancy_id, notes in db.execute(
    "SELECT id, notes FROM vacancy WHERE notes LIKE '%Контакты: %'"
).fetchall():
    kept, values = [], []
    for line in notes.splitlines():
        value = line[len(PREFIX):].strip() if line.startswith(PREFIX) else None
        if value and not value.startswith("@"):
            values.append(value)
        else:
            kept.append(line)
            skipped += bool(value)
    for value in values:
        moved += db.execute(
            "INSERT OR IGNORE INTO vacancy_contact (vacancy_id, value, match_key, added_by)"
            " VALUES (?, ?, ?, 'parse')",
            (vacancy_id, value, contact_key(value)),
        ).rowcount
    rest = "\n".join(kept).strip() or None
    db.execute("UPDATE vacancy SET notes = ? WHERE id = ?", (rest, vacancy_id))
db.commit()
print(f"перенесено {moved}, оставлено Telegram-ников {skipped}")
```

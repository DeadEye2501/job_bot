# Автозаполнение резюме

## Цель

Одна кнопка заполняет резюме человека на сайте агрегатора по профилю
приложения. Каждое заполненное в профиле поле попадает на сайт, причём в
самое подходящее место.

Это третий кусок работы «автозаполнение резюме на агрегаторах»: поля профиля →
резюме на агрегаторах → само автозаполнение. Опирается на обе предыдущие спеки:
«Новые поля профиля» и «Резюме на агрегаторах».

## Главное правило

**Агент идёт по устройству сайта, а данные раскладывает по их видам.** Порядок
обхода задаёт сайт: страница за страницей, раздел за разделом. Многие сайты не
показывают следующие поля и не пускают на следующую страницу, пока не
заполнены предыдущие. На каждой странице каждое поле получает свою часть
профиля по одной общей таблице «куда лучше / запасной путь».

## Запуск

- **«Перезаписать»** в строке резюме — агент стирает это резюме и заполняет
  его заново.
- **«Создать новое резюме»** справа от кнопки входа — агент заводит новое
  резюме и заполняет его. Название нового резюме — должность из профиля.
- Запуск — как у входа и «Прогнать сейчас»: действие человека, занимает место
  прогона, работает при любом режиме бота.
- После заполнения список резюме этого агрегатора сканируется заново: база —
  зеркало сайта, и новое резюме должно в ней появиться.

## Что перезаписывается

- **Резюме** (одно из нескольких или единственный профиль сайта) приводится к
  профилю приложения целиком. Лишнее удаляется: место работы, проект или
  навык, которых нет в профиле.
- **Личные данные, которые на сайте живут одним экземпляром на аккаунт**
  (имя, контакты, дата рождения и прочее вне резюме), перезаписываются по
  профилю при любом заполнении.
- Остановка посреди заполнения оставляет резюме заполненным наполовину;
  повторное нажатие перезаписывает его целиком. Своего «продолжить с места»
  нет.

## Куда кладутся данные

Общее правило одно: **каждая часть профиля ищет на сайте самое узкое
подходящее место; нет такого — спускается в ближайшее общее текстовое поле с
понятной подписью.** Таблица — следствие правила, а не список исключений:

| данные | куда лучше | запасной путь |
|---|---|---|
| личные данные (ФИО, латиница, дата рождения, пол, гражданство, город) | свои поля | — |
| контакты (почта, телефон, Telegram, GitHub, ссылка на резюме) | свои поля | «О себе» строкой «Контакты: …» |
| должность, грейд, формат работы, зарплата | свои поля | «О себе» |
| место работы | отдельная запись места работы: компания, должность, даты, обязанности, достижения, стек — каждое в своё поле | описание места работы: «Обязанности:» списком, «Достижения:» списком, «Стек:» через запятую |
| проект | раздел проектов или портфолио: название, ссылка, описание, стек | «О себе» списком: название, ссылка и одно предложение о проекте |
| навыки | виджет навыков сайта | «О себе» строкой «Навыки: …» |
| языки | свои поля с уровнем | «О себе» |
| образование | свой раздел | «О себе» |
| «О себе» | поле «О себе» | — |
| файл резюме, фото | загрузка файла | — |

- Правила латиницы, дат и ФИО — общие с откликателем (спека «Новые поля
  профиля»).
- Галочку согласия на обработку персональных данных, без которой сайт не
  сохраняет профиль, агент ставит сам. Оферты, платные услуги и подписки не
  принимает.

## Справочники сайта

Навыки, город, языки, грейды часто выбираются из списка сайта.

- Значение из списка берётся, только если это **то же самое** (другое
  написание, синоним из профиля) или **более широкое понятие, которое наше
  включает** (город → его область; узкий навык → язык, на котором он стоит).
- Наименее далёкий вариант из неподходящих не берётся никогда: «красный» не
  превращается ни в «белый», ни в «чёрный».
- Совпадения нет — данные идут запасным путём, текстом. Широкое понятие,
  выбранное вместо нашего, тоже тянет наше значение в текст: его на сайте
  иначе не будет.
- Обязательный список без подходящего варианта: «Другое» и наше значение
  текстом, если «Другое» есть; если нет — поле остаётся пустым (см.
  «Ошибки»).

## Страница: опись, раскладка, проверка

Для каждой страницы:

1. **Опись.** Код снимает со страницы все поля: подпись, вид, обязательность
   (готовое чтение поля страницы — `agent/page_fields`). Опись собирает код, а
   не агент: пропустить поле агент не может.
2. **Раскладка.** Агент сопоставляет полям части профиля и отдаёт раскладку
   страницы целиком одним вызовом инструмента. Каждый пункт запасного пути
   несёт обоснование: почему узкие поля из описи не подходят.
3. **Проверка.** Пункты запасного пути со своими обоснованиями и опись
   страницы уходят проверяющему — **один вызов на страницу**. По каждому
   пункту вердикт: «убедительно» — запасной путь разрешён; «неубедительно» — с
   причиной и, если видно, с полем, куда это ложится.
4. **Ввод.** Вписать на страницу можно только то, что есть в принятой
   раскладке, и только в то поле, за которым оно записано. Это держит код —
   тем же строгим вводом, что у отклика с подтверждением: принятая раскладка
   занимает место подтверждённого человеком.

- Отбитый пункт агент кладёт в узкое поле или присылает заново с новым
  обоснованием. Проверок на страницу — две, как у писем. После второго отказа
  пункт идёт в узкое поле или пропускается, и в журнал пишется, что
  проверяющий его не пропустил.
- Проверяющий — отдельный вызов той же модели чата, что проверяет письма.
- Сбой вызова (сеть, обрыв, непонятный ответ) — запасной путь разрешается, в
  журнал пишется строка об этом. Заполнение из-за сбоя проверки не стоит, как
  и проверка писем.
- Появились новые поля после заполнения прежних — опись снимается заново, и
  новые поля проходят тот же круг.

## Ошибки и отчёт

- **Необязательное поле**, которое нечем заполнить, пропускается: человек
  дозаполнит его сам или оставит пустым.
- **Обязательное поле, которое нечем заполнить, — ошибка.** Сайт не сохранит
  такую страницу, и заполнение на ней останавливается. В журнал — каких полей
  не хватило; внизу на время всплывает плашка ошибки «Не хватает данных для
  обязательных полей».
- **Журнал** — краткая сводка, без перечня каждого поля: сколько страниц
  пройдено, сколько данных ушло запасным путём, какие необязательные поля
  пропущены.
- **Успех** — всплывающая строка «Резюме заполнено», как у других действий
  карточки.

## Что переиспользуется

| что нужно | что уже есть | как |
|---|---|---|
| сессия агента в браузере агрегатора | `AgentKit`, `live_session`, профиль браузера агрегатора (`adapters/browser.py`) | ещё одна роль агента со своим заданием |
| роль со своими правилами | общая рамка и роли в `backend/agent/prompts/` | своя роль; запрет рамки «не менять профиль на сайте» снимает задача, как рамка и предусматривает |
| опись полей | `backend/agent/page_fields.py` | расширяется подписью поля |
| строгий ввод по принятому | строгий ввод отклика с подтверждением (`_strict` в `tools_browser.py`, `job.confirmed`) | принятая раскладка вместо подтверждённого человеком |
| проверка второй моделью с бюджетом | `factcheck_cover_letter` и инструмент письма с `_CHECKS_ALLOWED` | тот же приём: вызов, вердикт агенту текстом, две проверки |
| загрузка резюме и фото | `browser_attach_resume` и инструмент фото из спеки «Новые поля профиля» | без изменений |
| анкета для агента | `build_agent_profile` | без изменений |
| запуск из карточки | `launched_on_bot`, место прогона | ещё действия тем же путём |
| сканирование после заполнения | сканирование из спеки «Резюме на агрегаторах» | без изменений |

## Попутно: системные сообщения без точки

Всплывающие строки и плашки, которые сообщают итог действия или отказ
(«Вход проверен.», «Отклик записан.», тексты отказов в
`client/bridge/refusals.py` и подобные), пишутся в одном виде — **без точки на
конце**. Все такие сообщения сводятся к этому виду.

## Чего нет

- Подтверждения перед сохранением: свою анкету человек поправит руками, а
  письма живому человеку здесь не уходит.
- Оглядки на симуляцию отправки: она про письма работодателям.
- «Продолжить с места».
- Спора агента с проверяющим сверх двух проверок на страницу.

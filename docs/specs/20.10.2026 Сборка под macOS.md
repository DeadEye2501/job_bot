# Сборка под macOS

Итог разведки 20.10.2026: что мешает собрать и запустить JobBot на маке и чем это заменить.

## Цель

Вторая сборка — `.app` для macOS — рядом с нынешней Windows-сборкой, а не вместо неё. Windows-код остаётся как есть и продолжает собираться и работать. Всё, что завязано на WinAPI, получает мак-двойника; какой из двух работает, решается по `sys.platform` один раз, в одной точке. Поддерживаются обе ветки.

## Что уже кроссплатформенное

- Отрисовка. pywebview сам выбирает движок: WebView2 на Windows, WKWebView (системный WebKit) на маке через pyobjc. Фронт на Svelte, мост и `api/bridge.js` не меняются: `window.pywebview` и событие `pywebviewready` те же.
- Каталог данных — `config.py:17-28` уже разводит Windows, macOS и Linux.
- Замок единственной копии — `backend/single_instance.py:64-71` уже умеет `fcntl.flock` (но см. п. 3).
- `client/raise_window.py`, `client/window.py:221` — Windows-вызовы уже под проверкой платформы.
- `adapters/claude_code_process.py:56` — `CREATE_NO_WINDOW` берётся через `getattr`, на маке 0.
- Горячие клавиши (`client/web/state/keys.js:42`) учитывают Cmd.
- Pyrogram, Playwright, SQLAlchemy, keyring, httpx, mcp, uvicorn, anthropic — кроссплатформенные.

## Устройство: двойники и точка выбора

Windows-специфичное живёт в своих модулях, мак-двойник — рядом, с теми же именами функций. Выбор — одной строкой импорта по `sys.platform` в одном месте на каждый предмет; вызывающие импортируют из точки выбора и о платформе не знают. Абстрактных базовых классов и реестров не нужно: две реализации одних и тех же функций.

Совсем без правок существующих файлов не обойтись: там, где Windows-код вплетён в общий модуль, его надо вынести в Windows-модуль, а на его месте оставить точку выбора. Поведение на Windows при этом не меняется — меняется только место, где лежит код.

## Что мешает запуску

1. **`adapters/process_windows.py:10`** — `ctypes.WINFUNCTYPE` вычисляется при импорте; на маке его нет → `AttributeError`. Модуль тянут `adapters/browser.py:15`, а через него мост и окно — приложение не стартует.
   Двойник: `process_macos.has_window(pid)` через Quartz — `CGWindowListCopyWindowInfo`, поле `kCGWindowOwnerPID` (pyobjc-framework-Quartz). Точка выбора — там, где `browser.py` импортирует `has_window`.
2. **`adapters/app_tied_process.py:15,24`** — `from ctypes import wintypes` и `wintypes.HANDLE(-1).value` при импорте. Импорт `ctypes.wintypes` на маке под Python 3.13, скорее всего, проходит, но проверить надо. Сама привязка на маке пустая (см. п. 9). Безопаснее перенести Windows-часть в свой модуль, чтобы на маке `wintypes` не трогался вовсе.
3. **`backend/single_instance.py:38`** — `errno.EDEADLOCK` в `_BUSY`; на Darwin, по всей видимости, есть только `EDEADLK`. Модуль импортируется в `main.py` первым. Правка в одну строку: имя из `errno` берётся по платформе. Проверить на маке.
4. **`Pipfile:30`** — llama-cpp-python закреплён колесом `cp313-win_amd64`. Готового колеса macOS arm64 под 3.13 не найдено; на маке — сборка из исходников с `CMAKE_ARGS="-DGGML_METAL=on"` (нужны Xcode Command Line Tools, Python обязательно arm64, иначе соберётся x86 и будет в разы медленнее). В `Pipfile` — две строки с маркерами `sys_platform == 'win32'` и `sys_platform == 'darwin'`.
5. **`Pipfile.lock`** — собран на Windows: в нём `pywin32`, `pywin32-ctypes`, `pythonnet`, `clr-loader` без маркера платформы и нет `pyobjc-*`, нужных Cocoa-бэкенду pywebview. Lock пересобирается так, чтобы покрыть обе платформы (или мак-сборка ставит зависимости без lock).
6. **Spec сборки** — нынешний `JobBot.spec` остаётся для Windows; для мака — свой `JobBot-macos.spec`:
   - hidden import `keyring.backends.macOS` вместо `keyring.backends.Windows` — иначе keyring отдаст `fail.Keyring`, и `backend/crypto.py:29,47` откажет в запуске;
   - иконка `client/icon.icns` (собирается из `icon.png` через `iconutil`);
   - сборка onedir + `BUNDLE(...)` в `JobBot.app` с Info.plist (bundle id, `NSHighResolutionCapable`); onefile + windowed PyInstaller на маке не рекомендует;
   - подмодули `webview.platforms.cocoa` и pyobjc-фреймворки, если PyInstaller не найдёт их сам.

## Что ломает функции

7. **Поиск браузера — `adapters/browser.py:37, 59-94`.** Ищет по `PROGRAMFILES`/`LOCALAPPDATA` и `*.exe` — на маке не найдёт ничего, агент недоступен (`backend/agent/availability.py`).
   Двойник — список путей мака: `/Applications/<Имя>.app/Contents/MacOS/<бинарь>` и то же в `~/Applications` для Google Chrome, Opera, Brave Browser, Vivaldi, Yandex, Microsoft Edge. Каналы Playwright `chrome` и `msedge` на маке работают как есть.
8. **Конец входа на агрегатор — `adapters/browser.py:279-295`.** Ждёт исчезновения окна через `process_windows.has_window`. На маке браузер после закрытия окна обычно остаётся жить, так что ждать надо именно окно — двойник из п. 1 это и даёт.
9. **Привязка дочерних процессов — `adapters/app_tied_process.py`.** Job Object с `KILL_ON_JOB_CLOSE` на маке не существует; сейчас там ничего не делается, и при падении JobBot Claude Code, браузер и драйвер Playwright остаются сиротами.
   Двойник: дочерние процессы стартуют в своей группе (`start_new_session=True`), при штатном выходе группа гасится `os.killpg`; для аварийного выхода — сторож, ждущий смерти родителя через kqueue `NOTE_EXIT`. Полной гарантии при `kill -9` нет — это принятый предел.
   Отдельно: `browser.py:220` привязывает процесс по имени `node.exe`; на маке драйвер зовётся `node`.
10. **Поиск Claude Code — `adapters/claude_code.py:49-60`.** Windows-ветка (`.cmd`-обёртка, `claude.exe`) на маке не срабатывает, остаётся `shutil.which("claude")`. Но приложение, запущенное из Finder, получает урезанный PATH (`/usr/bin:/bin:/usr/sbin:/sbin`), и `~/.local/bin`, `/opt/homebrew/bin`, npm-global не видны — Claude Code «не установлен».
    Двойник: перебор известных мест установки (`~/.local/bin/claude`, `~/.claude/local/claude`, `/opt/homebrew/bin/claude`, `/usr/local/bin/claude`) либо PATH из login-shell (`$SHELL -lc 'echo $PATH'`).
11. **Открыть ссылку или файл — `client/bridge/desktop.py:115`.** `os.startfile` на маке нет — не открывается ни одна ссылка (`tg:`, `mailto:`, http) и ни одно вложение. Двойник: `subprocess.run(["open", target])`.
12. **Показать в папке — `client/bridge/desktop.py:84`.** `explorer /select,` → двойник `open -R <путь>`.
13. **Размер окна после мастера — `client/window_size.py:62`.** Импорт `webview.platforms.winforms` на маке — `ImportError`, `enter_main_app` (`client/bridge/wizard.py:103`) падает, окно остаётся маленьким и нерастягиваемым.
    Двойник: через `window.native` (NSWindow) — `styleMask |= NSWindowStyleMaskResizable`, `setMinSize_`, `setFrame_display_`, в главном потоке (`AppHelper.callAfter`).
14. **Окно о беде при старте — `client/trouble_box.py:35`.** `MessageBoxW`; на маке исключение уходит в журнал, человек о сбое не узнаёт. Двойник: `osascript -e 'display alert "…" message "…"'` (или `NSAlert`).
15. **Самообновление — `backend/updater.py`, `backend/update_download.py`, `adapters/github_release.py`.** Целиком под Windows: `creationflags=_DETACHED` (на POSIX — `ValueError`), `ctypes.windll`, `%TEMP%\JobBot-update.exe`, подмена одного exe рядом с `sys.executable`, файл релиза `JobBot.exe`.
    На маке подменяется весь `JobBot.app`: файл релиза своего имени (`JobBot-macos-arm64.zip`), распаковка рядом, ожидание выхода через `os.kill(pid, 0)`, замена каталога, запуск через `open -n`, отсоединение — `start_new_session=True`. Подмена файла внутри `.app` ломает подпись — менять только целиком.
    Первой мак-версии хватит без самообновления: тогда `client/bridge/app_update.py:33` (`updatable = frozen`) должен на маке давать «нельзя», иначе значок предложит обновление, которое не сработает.

    **Версии и релизы (решено 21.10.2026).** Номер версии один на обе системы — `VERSION` в `backend/app_version.py`: обе сборки выходят из одного кода, и номер описывает код, а не упаковку. Релиз на GitHub один на версию (тег `v` + номер), в нём два файла — `JobBot.exe` и `JobBot-macos-arm64.zip`. Отдельных тегов и релизов под каждую систему нет. Каждая сборка, проверяя обновление, смотрит последний релиз и ищет в нём только свой файл: мак не видит exe, Windows не видит zip. Релиз без своего файла этой сборке обновлением не считается — так же, как сейчас Windows-сборка не считает обновлением релиз без `JobBot.exe`. Исправление только для одной системы всё равно поднимает общий номер; что в нём для какой системы, говорит заметка релиза.

## Косметика и проверка вживую

16. **Шрифты.** `Segoe UI` (`client/web/styles/base.css:62`) и `Consolas` (`health-lamp.css:31`, `help-block.css:23`, `input.css:96`, `raw-text.css:62`) на маке отсутствуют; запасные прописаны (`system-ui`, моноширинный), но метрики иные — вёрстку проверить. Решение — добавить мак-шрифты в те же стеки (`-apple-system`, `SF Mono`/`Menlo`), Windows не затрагивается.
17. **`field-sizing: content`** (`styles/chat.css:232`, `styles/confirm-send.css:26`) — в WebKit только в свежих Safari; на старых macOS поля не растут по тексту. Проверить на целевой версии.
18. **`user-select: none`** (`base.css:71`) — проверить, что сборка добавляет `-webkit-`-префикс, иначе текст интерфейса станет выделяемым.
19. **`navigator.clipboard.writeText`** (`app/VacancyCard.svelte:210`) — в WKWebView на `http://127.0.0.1` скорее всего работает, проверить.
20. **Иконка окна** — `webview.start(icon=…)` с `.ico` Cocoa игнорирует; иконка Dock берётся из `.icns` бандла (п. 6).
21. **Повторный запуск** — на маке LaunchServices сам активирует уже открытое приложение; логика `raise_window` безвредна. Клик по иконке в Dock при скрытом окне — проверить, что окно возвращается.

Завязаны на Windows и на маке упадут или проверяют только Windows-ветку: `tests/test_config.py`, `tests/backend/test_single_instance.py:109`, `tests/adapters/test_browser_choice.py`, `tests/client/test_bridge_shell.py:175,253,271`, `tests/backend/test_updater.py`, `tests/adapters/test_claude_code.py:321-338`, `tests/backend/test_bot_update.py`, `tests/backend/test_entry_point.py`. `tests/adapters/test_app_tied_process.py` на других ОС уже пропускается. ## Сборка и выпуск

- **Где собирать.** PyInstaller не собирает под мак с Windows. Сборка — на GitHub Actions, раннер `macos-14`/`macos-15` (Apple Silicon, arm64); для публичного репозитория бесплатно. Intel-раннер `macos-13` GitHub выводит из работы — Intel-маки не поддерживаются.
- **Workflow:** checkout → Python 3.13 arm64 → Node → `npm ci && npm run build` в `client/web` → установка зависимостей (llama-cpp из исходников с Metal) → `pyinstaller JobBot-macos.spec` → zip `.app` → файл в релиз рядом с `JobBot.exe`.
- **Подпись.** Без аккаунта разработчика Apple (99 $ в год) приложение не подписано и не нотаризовано: Gatekeeper блокирует скачанное. Человек открывает его один раз правым кликом → «Открыть» (на новых macOS — «Системные настройки → Конфиденциальность и безопасность → Всё равно открыть») или командой `xattr -cr JobBot.app`. Для раздачи знакомым терпимо.
- **Проверка без мака** — только по логам Actions и отзывам того, кто запустит. Пункты 2, 3, 8, 13, 17-21 подтверждаются только вживую.
